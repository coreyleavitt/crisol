# RFC-0006 — Cross-entrypoint compile reuse: measure first, recover the redundant substrate

**Status:** Draft (stage 2 — architect rounds 1 & 2 applied; **one non-blocking open fork: FORK-R = the object-cache mechanism, native vs ccache vs sccache — only reached if Stage M greenlights Stage R**). Research-gated: Stage M's measurement is the decision gate for Stages R/S.
**Depends on:** RFC-0004 (incremental hermetic execution — reuses its `RunLedger`, telemetry/`run/v1` schema, `<stateDir>` + GC/`clean` machinery, the `ccprobe.ccVersion` toolchain probe, the hermeticity model, `closure.nim`'s nimcache-JSON parser, and the `spawnCompileStable` compile path this RFC instruments and extends). Independent of RFC-0005.
**Scope owner:** Corey
**Tracking issue:** #4

## Summary

crisol compiles each test entrypoint with a **private, per-slot nimcache** (`spawnCompileStable`, `runner.nim:379` — `--nimcache:<cachePath(ep)>_<pepIdx>`). On a compile-bound suite this recompiles the **entire shared dependency substrate once per entrypoint**, with zero cross-entrypoint reuse. On amoxtli (373 entrypoints, each cold-compiling the chronos + daemon stack; compile:run ratios of 100×–2400×) this is the single dominant cost of a cold run.

The per-entrypoint isolation is a **correct, deliberate default** — a naive shared `--nimcache` collides on the entry module and ORC whole-program link/init artifacts (CLAUDE.md: *NEVER a shared `--nimcache`*). This RFC recovers the redundant work **without** relaxing that safety.

The central, disciplining fact: **the value of this entire feature is bounded by one quantity nobody has measured — how much of the generated substrate is genuinely reusable across entrypoints under `--mm:orc`, weighted by the compile *time* it costs.** Under ORC's default whole-program dead-code elimination a "shared" module's generated `.c` is *tailored per program* (only reachable procs emitted; RTTI/trace procs and generic instantiations are whole-program-dependent) — **empirically confirmed** (round 1: two programs importing the same `std/strutils` produced different-MD5 `@psystem.nim.c`; identical programs under `--mm:refc` produced byte-identical output — the tailoring is genuinely ORC-concentrated). So reuse is **not** guaranteed by module identity; it must be *measured*, on the **exact key material Stage R would key on**, and weighted by **cc wall-time**, not bytes (see below).

Accordingly this RFC is **research-gated** and leads with epistemics, not mechanism:

1. **Stage M (unconditional) — measure.** Instrument the compile path to record, over a real run: (a) the **time-weighted cross-entrypoint reuse ratio** `r_time` of the *reusable* `.c` set (all modules except the per-entrypoint entry unit — see §File scoping), keyed on the same normalized material Stage R would use and weighted by each unit's measured cc time; and (b) the **compile cost split** (Nim codegen vs C compile vs link), computed overlap-aware. Also run a **same-entrypoint/cross-slot reproducibility check**. Evaluate Nim's `--incremental` (IC) as a **repeat-compile** baseline — *a different question* (see M-IC). Ship this as a durable `crisol` capability (a permanent reuse-ratio regression guard), not a throwaway script. **Its output, against a committed decision rule, selects the mechanism.**
2. **Stage R (conditional: `r_time` meaningful AND cc-bound) — recover.** A **content-keyed, cross-entrypoint object cache**: key the C-compile step on the *full cc input set* — normalized cc command + `.c` content + its full `cc -M` `#include`-closure manifest + `nimVersion` + `ccVersion` — serve the `.o` on a key hit **confirmed against the requester's own key preimage**, populate on miss, verify the stored `.o`'s checksum on read. **Sound only to the extent the key captures every cc input and a hit is confirmed, not merely digest-equal** (§Soundness). Managed under `<stateDir>`, **host-local in v1**, hermetic-adjacent, GC'd via a dedicated pass, hit-rate + net wall-clock impact reported.
3. **Stage S (conditional: `r_time` low AND a force-full-emission lever exists) — convert.** Opt-in `share-substrate` that relaxes DCE for declared substrate modules so their `.c` becomes entrypoint-independent, trading binary size / link cost for cacheability. **Gated on S0** — a prerequisite check that Nim even exposes such a lever (round 1: `--dce`/`deadCodeElim` was *not* found in `nim --fullhelp` on 2.2.10; Stage S may be infeasible as scoped). Higher risk, opt-in only, soundness-guarded.

Everything stays at **entrypoint-binary granularity** and **binary-opaque** identity (MEMORY.md → boundary-granularity-discriminator). The theoretically-optimal reuse — fusing all entrypoints into one bin-packed binary — is a **Non-Goal**: it would make crisol author test-program source and own the process model, crossing the boundary. This RFC recovers only the reuse that is sound *without* touching what an entrypoint is.

## Motivation

- **The dominant cold-run cost is redundant substrate compilation, and it is structural.** The cost is `N_entrypoints × substrate_compile_cost` with no cross-entrypoint sharing. On amoxtli that is 373 cold compiles of the same chronos stack. This dwarfs every per-test or per-run micro-optimization.
- **Per-slot nimcache is even less reuse than "per entrypoint."** The compile dir is `cachePath(ep) & "_" & $pepIdx` — slot-suffixed — so re-running the *same* entrypoint on a different slot recompiles it too. Nim's own within-nimcache incrementality only helps a repeat compile into the same dir, which crisol's slot model rarely reuses.
- **The naive fix is unsound in a way issue #4 under-diagnoses.** Sharing a nimcache does not merely collide on the entry module + link. Under ORC, non-main "substrate" modules emit **program-specific** `.c` (dead-code elimination emits only procs reachable from *this* entrypoint; RTTI/trace/generic-instantiation are whole-program-dependent — confirmed above). A cache that reasons *"module + flags ⇒ shareable object"* would serve objects **missing procs the other entrypoint needs**. This is why Stage R keys on **content + the full cc input set**, never on module identity.
- **The ceiling is unknown, so spending before measuring is the exact mistake to avoid.** If ORC-tailoring is small, most substrate `.c` is identical and a content-keyed cache recovers nearly the whole win, sound. If tailoring is large, only DCE-relaxation (Stage S) or nothing helps. Stage M measures which regime amoxtli is in before we build the wrong thing.
- **The measurement is only honest if it measures the right thing, weighted the right way.** Three traps, all found empirically across rounds 1–2: (a) every generated `.c` embeds a header line containing the per-slot absolute cc command, so a raw byte hash reports *everything* as distinct (`r ≈ 0`) even when the code is identical — Stage M **must normalize** (strip the compiler-command header; equivalently hash under `--compileOnly`, which omits it) before comparing; (b) `.c`-only identity is an *upper bound* on safely-reusable identity, because the cc also reads the module's full `#include` closure — so Stage M measures identity over the **same normalized key material Stage R keys on**, not bare `.c`; (c) a **size-weighted** ratio answers the wrong question — the decision is about compile *time*, and a suite can have most of its reusable *bytes* in one big identical file while most of its reusable *cc time* is in many small ORC-tailored non-identical ones (or vice-versa). Stage M therefore weights `r` by measured per-unit cc time (`r_time`), and reports size-weighted `r` only as a secondary (storage-planning) metric.
- **The reuse win, once real, must stay real.** A substrate refactor, flag change, or Nim upgrade can silently collapse `r_time`. The measurement is therefore a *permanent* capability (a `reuse-check` policy + ledger-driven drift guard, modeled on RFC-0004's `perf-check`), not a one-off.

## File scoping (read before Stage M and Stage R)

crisol's `closure.nim` decodes nimcache basenames: `@m<body>` = a module in the entrypoint's own package/dir tree; `@p<body>` = a module resolved via a search-path root (stdlib, a nimble package such as **chronos**, or `--path`). Round-1 finding (empirical): the substrate this RFC targets is largely **`@p`-prefixed**, and there can be **multiple `@m` files** (any same-directory local import), so "`@m*.nim.c`" is the wrong selector in both directions.

**The reusable set = every generated `.c` except the single entry unit.** The entry unit is the one whose basename matches the entrypoint's own filename (`@m<entrypointBasename>.nim.c`) — it carries `NimMain`/whole-program init and must stay per-entrypoint, together with the final link step. Stage M's denominator and Stage R's cache both operate on *the reusable set so defined*; the `@m`/`@p` prefix is not the discriminator. (Round-2 check: `{.compile.}`-provided vendor C files are correctly captured by this basename discriminator, not the prefix — no special case needed.)

**Manifest access (round-2 correction).** `closure.nim`'s `extractClosure` deliberately **filters out** stdlib/nimble paths (exactly this RFC's substrate) and drops the cc command, returning only in-tree `.nim` source paths — it is the wrong shape for M/R. Factor a shared low-level `parseCompileManifest(jsonPath): seq[(cPath, ccCmd)]` from the JSON-reading logic already in `closure.nim`, return the **unfiltered** `compile` array; `extractClosure` becomes a filter over its output, and M/R consume it raw.

**Committed decision rule** (tunable once Stage M reports real numbers, but pinned here so an implementer has a rule rather than a coin flip): let `cc%` = C-compile share of compile wall-time (overlap-aware) and `r_time` = **cc-time-weighted** reuse ratio over the reusable set on the normalized key material.
- `cc% ≥ 40` **and** `r_time ≥ 0.50` → **Stage R**.
- `cc% ≥ 40` **and** `0.20 ≤ r_time < 0.50` → marginal; revisit with the absolute cc-time saved (`r_time · cc-time`, now a true time estimate since `r_time` is time-weighted) before committing R.
- `cc% ≥ 40` **and** `r_time < 0.20` → **Stage S** if S0 finds a lever, else **close**.
- `cc% < 40` (codegen- or link-bound) → **close with no mechanism** — R and S both leave codegen and link per-entrypoint untouched, and the only lever that would help (bin-packing) is a locked Non-Goal.

The decision *procedure* is committed here; the *mechanism* is selected by data. Stages R and S are **pre-designed but conditional** — we author the branch we take. Committing to a bespoke shared-substrate mechanism **before** measuring `r_time` is precisely the failure this structure prevents.

**What "sound by construction" does and does not mean.** A content-keyed object cache is sound **only to the extent (a) its key captures every input the C compiler actually reads, and (b) a digest hit is *confirmed* against the requester's own key preimage, not trusted on the digest alone**. The full input set is: the **normalized** cc command (per-slot absolute paths stripped, but real flag deltas — e.g. a project `nim.cfg`'s `--passC:-DFOO`, visible in the JSON `compile` entries — kept), the `.c` content, the **full transitive `#include` closure** obtained via `cc -M`/`-MM` and hashed by content — *irrespective of whether a header resolves inside the nimcache or in `/usr/include`* (a distro header backport that patches a struct layout without moving a version string must invalidate; this is exactly what ccache's direct mode hashes, and narrower "nimcache-local only" scoping would miss it), plus **`nimVersion`** and **`ccVersion`** (RFC-0004's `SoundnessKey` carries both for the same reason — a toolchain bump can change `nimbase.h`/runtime layout even when a module's own `.c` looks unchanged). Keying on `.c`-content alone (issue #4's Direction 1) is **unsound** — it cannot detect a tailored header or a compiler upgrade. And even with a complete key, a fast non-cryptographic digest (crisol's `SoundnessKey` idiom is folded FNV-1a) over a persisted keyspace of hundreds of thousands of near-identical substrate `.c` **can collide**; the read-time payload checksum guards torn/bit-rotted writes but *not* collision (it checksums the stored bytes against themselves), so Stage R additionally stores and confirms the key preimage on lookup (§Stage R). A key that omits any input, or a hit trusted on digest alone, can serve a wrong `.o`; §Soundness states why that is not a self-contained concern.

## Stage M — measurement & instrumentation (unconditional)

**Goal:** produce, from a real run, the numbers that drive the committed decision rule — and leave behind a durable capability that keeps producing them. Every effectful step goes behind an **injectable `CompileDriver` seam** (mirroring `ccprobe.RunProc` / `cachedispatch.CacheSeams`) — the *same* seam Stage R's production path implements (see §Stage R; M and R are modes of one driver, not two abstractions), so slices are unit-testable against synthetic compiler output, never real (slow) `nim c` invocations — with **one** exception deliberately budgeted: a committed real-compiler golden fixture (below).

- **M0 — artifact telemetry substrate (prerequisite slice).** Round-1 finding: `RunLedger` has **no row-kind discriminator**; `parseRow`/`rowToJsonLine`/`compactLedger`/`computeFlakeRate` all assume the single exec-row shape, so writing artifact rows into the exec shards would pollute flake-rate/perf baselines or be truncated on compaction. Resolution: write artifact-identity rows to a **separate shard stream** `<stateDir>/ledger/artifacts/<pid>-<bootId>.ndjson`, leaving the tested exec-row parser untouched. **This stream gets its own compaction/GC pass** (analogous to `compactLedger`/`cleanOrphans` for the main ledger — round-2 gap: the artifact stream must not accumulate one shard per invocation forever). Lands before any M slice writes rows.
- **M-driver — split-compile measurement driver (prerequisite; mechanism-agnostic, resolves the M→R honesty knot).** M-cost-split and per-unit cc timing both require driving compilation as *codegen then per-file cc then link* rather than one opaque `nim c`. Rather than pretend this is free (round-1) or couple M to Stage R's hardened path (round-2 finding), extract it as an explicit Stage-M slice: the `CompileDriver` in **measure mode** — runs `nim c --compileOnly <ep>` (codegen + `.c` + `<bin>.json`), then replays each `(cFile, ccCmd)` **reproducing Nim's own `execCmdsInParallel` concurrency** (so the measured split matches real wall-clock, not summed CPU time), then `linkcmd`; it records **overlap-aware** codegen/cc/link spans and **per-unit cc wall time**, and does **no caching**. This driver is measurement-gated (the default compile path stays the monolithic `nim c` until Stage R greenlights making the driver the default), and is genuinely mechanism-agnostic — it is needed for honest `cc%`/`r_time` regardless of whether Stage R is ever built or which FORK-R arm wins. Stage R extends *this* driver with the objcache layer; it does not reinvent it.
- **M-golden-fixture (prerequisite for trusting normalization).** `tests/fixtures/tmp` is gitignored scratch — there is **no committed real-compiler artifact** in the repo today, so the seam's "synthetic output" tests have no anchor to real Nim 2.2.10 codegen. Capture and commit **one chronos-importing 2-entrypoint fixture** (real `.c` + `.json`, small) with a *known* shared substrate module, and assert (i) header-normalization yields byte-identical reusable `.c` across the two, and (ii) `r_time`/`r_size` compute to their closed-form expected values. This is the measurement's own test oracle — without it, Stage M could ship a number that tracks a mock's assumption rather than real ORC behavior. (The trivial stdlib-only case is not sufficient: it has no companion `.h` and no per-slot `-I` variance, so it never exercises the header-closure the soundness argument turns on.)
- **M-artifact-identity.** At the `spCompiling`→`spRunning` success transition (`runner.nim:642`, **not** the finalize/`extractClosure` site at ~1148 — a slot's `cacheDir` is overwritten on its next dispatch, so late reads lose earlier compiles), for each `.c` in the reusable set: **normalize** (see below), then hash the **Stage-R key material** (normalized `.c` + full `cc -M` `#include`-closure manifest). Record `(entrypoint-identity, artifact-basename, keyHash, sizeBytes, ccTimeUs)` to the artifact stream. `r_time` = cc-time-weighted fraction of the reusable set whose key-hash is shared by ≥2 entrypoints; `r_size` = the size-weighted analog (secondary). Both **segmented by group/config**. **Gating (round-2 gap):** hashing the reusable set on every compile of every run has a real, unbounded hot-path cost (whole substrate × N entrypoints, forever). M-artifact-identity is therefore **measurement-mode-gated by default**, threaded like `Slot.spec` (precedent: existing per-phase toggle), with a lightweight always-on summary counter only if measured cheap enough; the RFC does not assume it is free.
  - **`normalize()` (exact, not heuristic).** crisol *constructed* the per-slot `cacheDir`/`binDir` strings for this compile, so normalization is a literal substring-erase of those **known** strings from both the `.c` header block and the `ccCmd` — not a regex that guesses which paths "look like" slot paths (which risks over-stripping a real project `-I`). Round-2 additions: detect `@file` response-file arguments and inline-hash the referenced file's **content** (else a `.rsp`-only change is invisible); the `.c` header is a fixed 4-line comment block (verified against real 2.2.10 output) so header stripping is a bounded operation, not a parser.
- **M-cost-split.** Consume M-driver's overlap-aware spans to report Nim-codegen vs C-compile vs link shares. (No longer a standalone mechanism — it is a read over M-driver's output.)
- **M-IC-baseline.** Evaluate Nim's `--incremental` (IC) on amoxtli's ORC stack. IC persists a rod-file module DB to speed **re-compiling the same program across edits** — it does *not* share compiled state across 373 *distinct* main modules, which is this RFC's problem. So M-IC answers "how much does IC help the *repeat*-compile case?" — useful context, but a favorable result does **not** close this RFC. (IC is also perennially experimental with ORC — tested, never assumed.)
- **M-report.** Modeled on RFC-0004's `perf-check` and RFC-0005's `cacheStats`, *not* an ambiguous "mode." **Measurement and alerting are split** (round-2): the `run/v1` block is emitted **unconditionally** (cheap, useful context regardless of outcome); the *alerting policy* `reuse-check { alert-below 0.5 }` is a separate surface whose default-on-ness is gated on Stage R actually being adopted — down the "close, no mechanism" branch a consumer must not carry a permanent drift alarm on a ratio that gates nothing. The `run/v1` block has a pinned shape, **segmented** (round-2 self-contradiction fix — the block is per-segment, not a single flat aggregate, matching the by-group/config requirement): a `compile` object holding `{ segments: [ { groupId, rTime, rSize, ccPct, codegenPct, linkPct, reproducible, artifactsTotal, artifactsShared, bytesTotal, bytesShared } ], … }`. Note `rSize = bytesShared / bytesTotal` and `artifactsShared/artifactsTotal` are derived from the raw counts (recorded for legibility, like `perf-check`'s derived `regressed`). Drift is read from the artifact stream the way perf-regression reads `median + k·MAD` from history.

Stage M ships value regardless of outcome: even if `cc%` is low and we build nothing further, the suite gains an overlap-aware compile-cost breakdown and a time-weighted reuse ratio it never had.

**Ambient-toolchain hygiene (round-2 gap).** Many CI base images wrap `cc` via ccache or set `CCACHE_*` ambiently, which would make M-driver's repeat cc invocations artificially fast and inflate/deflate the measured `cc%` — biasing the decision gate. Stage M **forces `CCACHE_DISABLE=1`** (and equivalents) for its own measurement invocations so `cc%`/`r_time` reflect the raw toolchain, and M-report records whether an ambient wrapper was detected.

## Stage R — content-keyed cross-entrypoint object cache (conditional)

Keeps per-entrypoint nimcache isolation (the entry `.c` + link stay private — the collision is real and confined there); shares only what is content-identical at the `.c → .o` boundary, over the reusable set.

**Mechanism — a crisol compile-worker child (round-2 rewrite; supersedes the generated shell script).** The `Slot` type has exactly one `pid` and a two-value `spCompiling/spRunning` phase. The round-1 shell-script sketch (author `sh <script>`, forkExec it) had three defects that four round-2 lenses converged on: it was a *stringly-typed shell surface* crisol's argv-array `forkExec` compile path never had (injection via a stateDir path with a space, a `--passC` metacharacter); it was secretly *two* sequential forked children (`--compileOnly` then the script) with in-process key computation between them — the very multi-pid state machine the re-slice claimed to avoid; and it forced objcache store/checksum logic to be *reimplemented in shell*, contradicting "factored, not hand-copied a third time." All three dissolve under one mechanism:

> crisol re-execs **itself** as `crisol --internal-compile-worker <plan.json>`, spawned via the **existing argv-array `forkExec`** (`runner.nim:393`) as the slot's single child — so `killpg`/`procGroupRssBytes`/timeout semantics are unchanged, and the scheduler still sees one pid with one `spCompiling→spRunning` transition. The worker is a crisol process, so it has `objcache.nim` / `closure.nim` / `ioutils` in-process; **no shell text is ever generated or executed.** The `plan.json` (authored by the parent) carries the entrypoint, flags, mode, and objcache path.

**Precondition made explicit (M-artifact-identity pass b2/b3): the self-reexec worker requires a host binary whose `main()` actually dispatches the internal token.** "Re-execs itself" is only sound when the currently-running process provably handles `--internal-measure-compile`/`--internal-compile-worker` — true of the crisol CLI (whose `runMain` special-cases the token before subcommand dispatch) but NOT generally true of a process merely linking crisol as a library. `Config.workerBinary` (plumbed from `RunOptions.workerBinary`) makes this the explicit seam: the CLI supplies its own `getAppFilename()`; a library consumer embedding crisol (e.g. calling `api.runTests()` from its own binary) must set `RunOptions.workerBinary` to a binary that dispatches the token to get measurement/reuse. Left unset, `spawnCompileStable` never guesses with `getAppFilename()` — it degrades to a plain monolithic `nim c` (measurement/reuse skipped) rather than re-execing an arbitrary host process, which would otherwise recurse unboundedly until the compile watchdog kills it.

The worker, in one process:
1. runs `nim c --compileOnly <ep>` as its own child (a grandchild of the slot, same process group) → codegen + `.c` + the `<nimcache>/<bin>.json` manifest.
2. parses it with `parseCompileManifest` (raw, unfiltered — see §File scoping). For each reusable `(cFile, ccCmd)`: computes the full key; on a **confirmed** hit (§key) `cp`s the verified `.o` into the slot's nimcache at the exact path `linkcmd` expects; on miss runs `ccCmd`, **gates on its exit status** (a killed/OOM'd cc must abort, never populate a truncated `.o`), then reads the freshly-produced `.o` and stores it (§store). cc misses are run with M-driver's `execCmdsInParallel`-matched concurrency.
3. runs `linkcmd`.
4. **Escape hatch (the missing fallback, now in-process):** on *any* objcache-layer error — manifest parse failure, lookup/store I/O error, a corruption/collision-confirmation mismatch — the worker abandons the split path and falls back to a plain monolithic `nim c` for the whole entrypoint, exiting exactly as today's `spawnCompileStable` would. A split-compile bug can therefore never harden into a compile failure the user cannot bypass. `--no-objcache` selects this monolithic path from the outset.

Because the worker *is* Nim, **all objcache read/verify/store runs in tested Nim code** (`atomicPutFile` + checksum, never shell), and the "two sequential children" problem is gone — the parent scheduler sees one worker child; the `--compileOnly` and cc invocations are the worker's own children inside the shared process group.

**The `CompileDriver` seam (one seam, two modes).** `CompileDriver { compileOnly, runCc, link }` (closure-field object, crisol idiom). Stage M's tests inject synthetic procs; **measure mode** (M-driver) times spans and does not cache; **cache mode** (this stage) implements `runCc` as objcache-lookup-or-compile-and-store. The worker binary is the production implementation of both modes — M and R are not two abstractions, they are two configurations of one.

**Types & store (crisol idiom):** a per-key store `ObjectCache` (`objcache.nim`) at `<stateDir>/objcache/v<fmt>/<keyHash>.o`, behind an injectable `ObjCacheSeams { lookup: proc(keyHash, keyPreimage): Option[string]; store: proc(keyHash, keyPreimage, objPath): bool }` (mirroring `CacheSeams`), and an `ObjCacheDecision` enum `{ ocdHit, ocdMissCompiled, ocdStored, ocdDisabled, ocdSoftCapSkipped, ocdCollisionReject }`. **Enum discipline (round-2, from RFC-0004's own M8 fix):** these are documented as mutually-exclusive *terminal* per-object outcomes — `ocdMissCompiled` = compiled locally, not stored; `ocdStored` = compiled locally and stored; `ocdCollisionReject` = digest hit but preimage mismatch (treated as a miss + logged forensically); never a mix. Store integrity mirrors `resultcache` but accounts for the raw-blob difference (round-2 — an `.o` is not JSON, so the checksum cannot live *inside* it): **a two-artifact commit** — `<keyHash>.o` (the object) plus `<keyHash>.meta` (an FNV `payloadChecksum` **and** the key **preimage**), both written via `ioutils.atomicPutFile` (O_EXCL-tmp + `writeAllFd` + `rename(2)`, factored out of `resultcache` and shared), object written **before** meta, and a **missing/unreadable `.meta` ⇒ treat as miss** (so a crash between the two renames is a miss, never a false hit). On lookup: confirm the stored preimage equals the requester's freshly-computed preimage (collision defense, §Soundness) **and** the payload checksum verifies (torn-write defense); either failure ⇒ miss.

**Key (the full cc input set — see §Soundness):** `normalize(ccCommand) ⊕ cContent ⊕ ccDashM_IncludeClosure ⊕ nimVersion ⊕ ccVersion`, digested to the `<keyHash>` filename; the **full preimage** (or a wide/cryptographic hash of it) is stored in `.meta` and confirmed on hit. `normalize` strips the known per-slot absolute strings while preserving real flag deltas and inlines `@response-file` content (§M `normalize`).

Slices (conditional): **R0** resolve FORK-R · **R1** `objcache.nim` + `ObjCacheSeams` + `ObjCacheDecision` + shared `atomicPutFile` + two-artifact commit + read-time checksum **and** preimage confirmation · **R2** wire the objcache layer into the (already-built, already-parity-hardened) M-driver worker → cache mode + the monolithic-fallback escape hatch · **R3** host-local scope + compile-env constraint documented, object reuse provably outside the result-soundness key · **R4** dedicated `gcObjCache` LRU pass called from `cleanOrphans` (**not** `pruneDir` — `objcache/` is a third sibling dir `pruneDir` never walks, so the risk is *unbounded growth*, not accidental deletion; round-2 corrects the round-1 rationale), preserving **every** `v<N>` subtree from cross-version deletion (matching `resultcache`'s multi-version contract) and sweeping orphaned `.tmp` from crashed writers (matching `resultcache` L8) · **R5** `ObjCacheDecision` hit-rate + reused-bytes **and net wall-clock impact including CI cache save/restore time** (round-2 — a benefit-only report can hide that a large `.o` store costs more to shuttle through a network-backed CI cache than it saves; Stage S got this accounting as S4, Stage R needs the symmetric one) in `run/v1` + summary, tied to the M artifact stream so drift is visible.

**Concurrency:** two slots missing the same key are, by construction, compiling byte-identical input, so last-writer-wins on the atomic rename is sound (functional `.o` equivalence is all that's needed). A *distinct*-input digest collision is a different event and is caught by preimage confirmation on lookup (`ocdCollisionReject`), not by last-writer-wins. Known efficiency (not correctness) gap: with a cold cache and high parallelism, many slots miss the same key before any populates it (no single-flight dedup), so first-wave realized savings run below `r_time`. Documented in R2/R5, not fixed in v1.

**Scope & hermeticity (host-local v1):** the compile phase spawns via raw `forkExec`, *not* the hermetic `forkExecEnvScratch` used for the run — so ambient cc env (`CPATH`, `C_INCLUDE_PATH`, `LIBRARY_PATH`, `CCACHE_*`, …) is *not* captured in the key. Within one `crisol run` every compile inherits one env, so this is a non-issue; **across** hosts/runners sharing a cache dir it is a real gap. Therefore the objcache is **host-local in v1** (a stated constraint). A native Stage R additionally forces `CCACHE_DISABLE=1` for its own cc invocations, or explicitly accepts stacking with a rationale (FORK-R). A cross-host object cache is deferred to the RFC-0005 door (§Relationship), and would require explicit compile-env capture.

## Stage S — shareability conversion (conditional: `r_time` low)

If `r_time` is low because ORC tailors heavily, no content cache helps — but we might *make* substrate `.c` entrypoint-independent by forcing full-proc emission for declared modules, trading larger `.c`/link for cacheability. **Opt-in only, never default.**

- **S0 — capability check (prerequisite, independent of `r_time`).** Does Nim expose a force-full-emission lever at all? Round-1 finding: no `--dce`/`deadCodeElim` switch appeared in `nim --fullhelp` on 2.2.10 (legacy `{.deadCodeElim.}` was made permanently-on and removed years ago). If no global *or* per-module lever exists, **Stage S is not buildable as scoped** — the decision tree's "r_time low" branch then terminates in *close with no mechanism*, not "do Stage S." S0 resolves this before any S design work. Candidate levers to check: `{.used.}`/export-marker pragmas, a forced-instantiation shim module, or `--expandArc`-adjacent options.
- **S1 — config surface** (`share-substrate` module list). **Global-only in v1** (round-1 ergonomics finding): per-group divergence silently fragments the reuse pool into islands with no diagnostic; if per-group is ever added it must emit a warning when groups declare different sets. **Populating the list is data-driven, not guesswork (round-2 gap):** Stage M's report gains a **per-artifact-basename breakdown** (top-N by cc time / by size, shared vs not) so a user reaching S1 sees exactly which modules are the largest non-shared offenders, rather than guessing at the moment the RFC's own epistemics say not to.
- **S2 — emit-all threading** for declared modules (whatever S0 found; global flag is the crude fallback).
- **S3 — soundness guard (the genuinely deep part).** Detect when relaxation did *not* actually yield identical `.c` across entrypoints and refuse to claim reuse rather than serve wrong objects; composes with Stage R's content-keying + preimage confirmation as the backstop.
- **S4 — measured-tradeoff report** (net win/loss vs baseline, so the opt-in is data-justified per project).

**Adjacent alternative (noted, not selected):** a **precompiled substrate static-lib SEED** — compile the declared substrate once per flag-combination into a `.a` and link each entrypoint's thin per-entrypoint object against it — is a more direct route than "relax DCE so R's cache serves it," but needs an ORC-whole-program-init-friendly boundary. Recorded as an option to weigh at R0/S0 time, not a committed path.

## Wire / schema touchpoints (additive, RFC-0004 style)

- **Separate artifact shard stream** `<stateDir>/ledger/artifacts/` (M0) with its own compaction/GC — the exec-row `parseRow`/`compactLedger`/`computeFlakeRate` path is untouched.
- `run/v1` schema revision bump (additive **segmented** `compile` block, pinned shape above; plus Stage R's object-cache hit-rate + net-impact). `loadLastRun`'s `schemaRevision > max ⇒ safe cold-start` already tolerates this.
- New config: `reuse-check { alert-below … }` (Stage M alerting policy, gated on R adoption); **object-cache knobs as flat top-level scalars** — `objcacheMaxEntries`, `objcacheMaxAgeDays` (round-2 — matching the **landed** `resultcache` config shape `maxCacheEntries`/`cacheMaxAgeDays`, not RFC-0005's unlanded block idiom; the two caches must not diverge in config style); `share-substrate` global list (Stage S). Parsed in the existing KDL `docToConfig` path. `--no-objcache` invocation flag: **fully reverts to the monolithic `nim c` path** (not merely disabling cache read/write), giving users an escape hatch from the split-compile mechanism itself. It is **independent** of `--no-cache` (the result cache) — neither implies the other; documented to forestall the "`--no-cache` disables *the* cache" assumption. No tri-state: the object cache's soundness is unconditional, so there is no consumer-declared-assumption opt-out to model.
- **Compile wall-time regression guard (round-2 gap).** RFC-0004's `perf-check` guards *run* duration; nothing guards *compile* duration. Once the worker becomes the default compile path, a few-`.c`/low-reuse entrypoint could regress (process-spawn × N + `cp` overhead exceeding cache wins) with no telemetry catching it. Track per-entrypoint/aggregate absolute compile wall-time under the same `median + k·MAD` idiom, independent of `r_time`.
- `crisol clean` summary line extended for the object cache; `gcObjCache` added alongside `gcResultCache` in `cleanOrphans`.
- **CI-persistence contract:** RFC-0004's CI doc enumerates persisting `<stateDir>/cache/` + `ledger/`; this RFC **adds `<stateDir>/objcache/`** to that list (else ephemeral CI silently loses all cross-run object reuse — the majority use case), with the R5 net-impact caveat that on network-backed CI cache tiers the store's own save/restore cost must be weighed.
- **`--changed`-narrowed runs:** `r_time`/M-report are statistically meaningless on a 1–2-entrypoint git-diff-narrowed subset; the report is marked low-confidence (and `reuse-check` suppressed) unless the run covers a representative entrypoint count.

## Relationship to RFC-0005 (no dependency; coordination + a door left open)

RFC-0005 (distributed *result* cache + trust) and this RFC are **orthogonal**: 0005 skips the *run* by sharing `CachedResult` across hosts; 0006 skips redundant *compile* work within a single cold build. Neither needs anything the other produces, and 0006 must **not** wait on 0005 (which is paused on its crypto fork). Two couplings:

1. **Shared RFC-0004 substrate — coordination, not dependency.** Both extend the same surfaces (`run/v1` schema revision, `clean.nim` GC, `<stateDir>` layout, KDL config). Additive and non-conflicting by design, but same files — whichever lands second rebases. In practice 0006 proceeds first (0005 is blocked); 0005 slots in beside it on resume.
2. **A door left open, deliberately not walked through now.** 0005 introduces a `CacheBackend` port + trust model for a distributed, content-addressed, attested store. A **future** distributed object cache (share `.o` across hosts — sccache / Bazel-RBE-cache class) would naturally be a tenant of that port, **and would need the compile-env capture Stage R defers**. This RFC's object cache is **host-local in v1 and stays that way**; forcing it through 0005's distributed-trust port before a distributed-object requirement exists is premature abstraction. The door is noted so the eventual unification is cheap; it is **not** a coupling now. (Note: if FORK-R selects **sccache**, this door is already half-built — sccache's S3/redis backends are the distributed tier, and its mature content-addressing already solves the collision-confirmation problem the native path hand-rolls.)

## Open forks

- **FORK-R (Stage R mechanism) — native `objcache.nim` vs external `ccache` vs `sccache`.** Rounds 1–2 sharpened the tension in both directions, so this is a genuine, informed fork (not a lean I can just make):
  - *Native* — dependency-free (crisol's demonstrated discipline), composes directly with `<stateDir>`/GC/telemetry/ledger, and requires **zero consumer-side changes** (crisol already controls its own `--compileOnly` + explicit cc via the worker). **But** it is new correctness-critical surface, and it must **reimplement the two things ccache exists to provide**: header-manifest hashing (the `cc -M` closure) *and* adequately-wide collision-resistant content-addressing with manifest confirmation (round-2 depth finding — a folded-FNV digest over near-identical substrate is a real collision surface the preimage-confirmation defense exists to cover).
  - *ccache* — battle-tested; its **direct mode already solves both** the `#include`-closure soundness problem and the collision problem the native path must hand-roll, and (bonus) it wraps `cc` so it works with the *monolithic* `nim c` — no split-compile worker needed on this arm at all. **But** it must be installed and wired in **every consumer's** toolchain image (crisol cannot add a dependency on a consumer's behalf — crisol's compile runs `nim c`/`cc` inside the *consumer's* container), and its own dir/GC/env fight the `<stateDir>`/allowlist model.
  - *sccache* — same content-addressed niche, **plus native S3/redis backends** that map directly onto RFC-0005's distributed-object door — the best fit *if* cross-host object sharing is a near-term goal; same consumer-image cost as ccache.
  - **Not blocking** — only reached if Stage M greenlights Stage R. Belongs to R0 / a future round once `r_time` is known. Recorded, not resolved. (Note the asymmetry the worker rewrite surfaces: the split-compile worker is a **native-arm** cost; the ccache/sccache arms reuse the monolithic `nim c` and skip it.)
- **No fork blocks Stage M** (unconditional; M-driver is mechanism-agnostic and needed on every branch).

## Non-Goals (locked)

- **Bin-packed / unified test binary.** The theoretically-optimal compile-reuse strategy, and exactly why it is excluded: it makes crisol **author test-program source and own the process model**, dropping binary-opaque entrypoint-granularity identity — the [[boundary-granularity-discriminator]] backtrack. Recorded so the RFC states *why* that ceiling is left on the table.
- **Persistent Nim compiler-server / daemon** (keep codegen state warm across the 373 small compiles — the lever that *would* help the codegen-bound branch). Researched-and-closed like S0's `--dce` check: mainline Nim exposes no such server/daemon mode today (distinct from disk-based `--incremental`, which M-IC evaluates). Flagged for revisit only if upstream adds one.
- **Dynlib-shared ORC heap** (substrate as a `.so` all entrypoints link). ORC's cycle collector and `PNimType`/RTTI tables are whole-program structures with no supported split-heap / cross-`.so` sharing model in mainline Nim. Researched dead-end, not v1.
- **Centralizing `.c → .o` in an external build graph** (ninja/make over all entrypoints) — essentially the ccache arm of FORK-R plus a scheduler; not pursued separately because crisol's own slot scheduler already provides the parallelism, and the compile-worker keeps orchestration in-process.
- **Cross-*project* object-cache sharing via a shared `<stateDir>` (v1).** Tempting — two repos vendoring the same chronos pin *could* share `.o` — but crisol's whole-run `F_SETLK` lock is scoped to `<stateDir>`, so pointing two unrelated projects' `CRISOL_STATE_DIR` at one directory would **serialize their entire test runs** against each other (round-2 finding: the exact CI pattern this RFC would otherwise incentivize). v1 stance: document sharing `<stateDir>` across unrelated projects as an anti-pattern; a future dedicated `CRISOL_OBJCACHE_DIR` (independent of the run-serializing lock) is the door to cross-project reuse, not in v1.
- **Reducing N** (consumer-side dep-light extraction). Real but marginal and the consumer's job, not crisol's.
- **Sub-binary control of any kind.** Layer-2-crossing; excluded per RFC-0004.
- **Changing the result-cache soundness model.** Object reuse is a compile-time transport (but see §Soundness for why its correctness is still load-bearing for RFC-0004).

## Soundness invariant (preserve verbatim in any refactor)

> Per-entrypoint nimcache isolation (the entry `.c` unit + ORC whole-program init + link) is **never** relaxed. Cross-entrypoint reuse happens **only** at the `.c → .o` boundary over the reusable set, **only** when the **full cc input set is key-identical** — normalized cc command + `.c` content + full `cc -M` `#include`-closure manifest + `nimVersion` + `ccVersion` — **the digest hit is confirmed against the requester's own stored key preimage** (a digest match alone is insufficient — a non-cryptographic digest over near-identical substrate can collide), **and** the stored `.o`'s checksum verifies on read. **Stage R's soundness is a *precondition* for RFC-0004's, not a severable concern:** an object cache that serves a wrong `.o` (mismatched key *or* undetected collision) yields a binary that silently diverges from a from-scratch compile while its `SoundnessKey` (computed from source/toolchain/flags) looks normal — if that binary passes on attempt 1 under achieved hermeticity, RFC-0004 caches the wrong result under a legitimate key and serves it indefinitely, polluting the ledger's flake-rate and perf baselines. The object-cache key never *appears inside* the `SoundnessKey`, but an unsound object cache can taint what is stored *under* one. Treat Stage R's key-completeness and hit-confirmation (above) as load-bearing for the whole engine.

## Context

- **Compiler facts verified in rounds 1–2** (against Nim 2.2.10 in-container + vendored compiler source + real nimcache artifacts): ORC tailors "shared" module `.c` per program (byte-identical under refc, divergent under orc); `@m` = entrypoint-tree module, `@p` = search-path module (chronos is `@p`); multiple `@m` files possible; every `.c` embeds a fixed 4-line per-slot cc-command header (defeats naive hashing; stripping it made two same-entrypoint compiles byte-identical) with an unconditional Nim-version stamp; the per-slot-varying cc material observed was only `-o <path>` + the positional `.c` path (both under the known slot `cacheDir` prefix crisol constructs); `nim c --compileOnly` emits codegen + `.c` + `<bin>.json` (cc cmds + `linkcmd`) with no cc/link; `closure.nim`'s `extractClosure` **filters out** stdlib/nimble (needs a raw `parseCompileManifest`); the whole-process `F_SETLK` lock makes any two `crisol run`/`clean` invocations mutually exclusive (safety, but also the cross-project serialization cost above); no `--dce` lever found in `nim --fullhelp` (Stage S S0 must confirm).
