The RFC's A1f bullet text should be amended to match at the next doc pass. **Three round-2 amendments flagged for veto, not forks** (recommendations applied per no-fake-forks):
  1. **Interrupt never persists `lastrun.json`** (stdout run/v2 with `interrupted:true` only). Invariant: a never-observed entrypoint must not silently leave the `--failed` selection; merging two runs' entries into one document fabricates a report no run produced. Veto ⇒ the merged-persist variant (this run's observed + prior entries for unobserved) is the fallback, and the A1d-i field table gains per-entry provenance.
  2. **`lsUnsupported` ⇒ cacheable-with-label; `lsFailed` ⇒ uncacheable** (§6). Extends the locked `toUnobservable` posture to limits; without it, any Windows config requesting `openFiles` permanently loses caching. Veto ⇒ strict RFC-0004 reading (requested-not-achieved always refuses).
  3. **Round-1's interrupt partial-results amendment stands** (unchanged from round 1, still veto-able as documented there; now fully specified — emission set, facade contract, no-ledger, no-persist).
