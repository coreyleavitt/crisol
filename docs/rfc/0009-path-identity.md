# RFC-0009 — Path identity: `TrackedPath` and the Windows suite

**Status:** DRAFT — build in progress 2026-09-11. A0-spike DONE and canonicalMerge/CanonicalSet REMOVED (Nim canonicalizes module identity to on-disk case → keyBytes deterministic by construction; design simpler; CI 34570358383 + 34572703298 green, macos APFS + windows NTFS). Round-3 review done (5 fable lenses); ~29 fixes + two calls applied. NEXT SLICE: A1 (paths.nim).
**Depends on:** RFC-0001 (closure/dep-graph path scheme), RFC-0004 (hermetic execution), RFC-0005 (attested cache wire — cache keys must stay portable), RFC-0007 (execution substrate; `process/windows` compiles+runs, D2b is RFC-0009-gated)
**Precedes:** —
**Followed by:** RFC-0008 (observed inputs) — `classify` is the **mandatory** identity boundary for the input observer's runtime-observed native paths; observed-path identity is `TrackedPath` from day one (an observed native path that lands `pcOutside` is content-hash-only/uncacheable — Contract impacts), or 0008 reinstates the un-reduced entry point 0009 closes.
**Closes / absorbs:** RFC-0007 D2b (test-suite de-POSIX + `windows-latest` FULL conformance leg + full-suite windows green)
**Scope owner:** Corey

## Summary

crisol's path handling is correct on Linux by accident: it treats a filesystem path as a POSIX byte-string, canonicalized ad hoc with `normalizedPath`/`absolutePath`/`expandFilename` at ~40 call sites and compared, deduplicated, and *hashed into cache keys* as a raw `string`. The one place that already got it right — `closure.nim` returns membership as **project-relative, forward-slash** paths (`closure.nim:163`), the same scheme `Entrypoint.path` and the dep-graph keys use — proves the canonical form exists but is unenforced: nothing stops a native Windows spelling (`C:\Proj\Tests\Foo.nim`, backslashes, drive-letter case, `\\?\` prefix, 8.3 short name) from entering that scheme un-reduced, and nothing folds case on a case-insensitive volume. The result on Windows (and on a case-insensitive macOS volume) is silent: a file referenced two ways splits into two closure members, two dep-graph nodes, and — worst — **two attested cache keys**, so impact-selection over-selects and the distributed cache never hits. And the scheme was never actually "project-relative" — a `depRoot` member (legitimately outside `projectRoot`) already falls through to a raw absolute native spelling (`fnv.nim:68`'s `if relPath.isAbsolute` branch is the proof), baking a machine-local path directly into an attested cache key.

This RFC replaces the ad-hoc string with a designed identity:

1. **`TrackedPath`** — a distinct type that *is* crisol's canonical, portable identity of a file tracked under some root, project or dependency. Identity is root-tagged: `(rootTag, rel)`, where `rootTag` names *which* tracked root the path is relative to (project = tag 0; each configured dep root gets a stable tag by name/order). The whole codebase compares, dedups, keys, and hashes `TrackedPath`, never a raw `string`, and never a bare project-relative guess at what root a file belongs to.
2. **One entry boundary** (`classify`) that reduces any native OS spelling to a total *classification* against the project root and every configured dep root — drive-letter/UNC normalization, `\`→`/`, `.`/`..` resolution, root relativization and tagging, and a **case-fold policy tied to a probed filesystem capability, per root**, not a platform `#define` (a case-insensitive APFS volume needs the same fold a Windows NTFS volume does; a case-sensitive Windows mount needs none; a dep root on a different volume than the project root needs its own answer). Textual, not inode-backed: the identity must be stable for files that do not exist yet (diff targets, generated outputs) and portable into RFC-0005's attested wire, which a volume-local file-id can never be.
3. **The Windows suite** — the test suite itself imports `std/posix` in 74 files (measured; RFC-0007 D2b's "~73"); RFC-0007 parked this as D2b under this RFC because de-POSIX-ing the suite requires the path identity to compare correctly first. This RFC lands the de-POSIX sweep, widens the `windows-latest` leg from the D2a CLI smoke to the FULL conformance suite, and takes full-suite Windows green — RFC-0007's own stated acceptance for D2b.

## Motivation

- **RFC-0007 D2b is blocked on exactly this.** RFC-0007 proved the *product* (`crisol run --json`) compiles and runs on Windows (D2a, CI-green all five legs), but its full-suite green "remains RFC-0009's acceptance": the 74 `std/posix`-importing test files cannot compile on Windows, and the path comparisons they exercise are wrong there until identity folds case and normalizes separators. That is the escalation boundary the /loop stopped at.
- **Cache correctness, not just Windows.** The cache-key split is a *correctness* bug the moment crisol runs on any case-insensitive volume — including a default macOS APFS volume — not a Windows-only cosmetic. Two spellings of one source → two `StoredEntry` keys → a cold cache that looks warm-eligible. RFC-0005 froze the attested wire; a path-identity fix that changed the key *shape* after 0005 shipped would invalidate every attested entry fleet-wide, so a project-root-relative identity must reduce to the *same* forward-slash string the wire already carries — a canonicalization tightening, not a key reshape.
- **Multi-root identity was undefined, and it leaked.** `closure.toProjectRelative` only knows one root; a `depRoot` member falls through to a raw absolute native spelling the instant it isn't under `projectRoot`. A type named "project-relative" cannot represent that case at all — the code already needed more than one root, the type must say so, and the key it produces today is unportable by construction, not by accident.
- **Selection soundness.** crisol's entire value is precise+sound test *selection* (MEMORY → crisol-value-is-selection): the impact closure is a set membership test over paths. On a case-insensitive volume a diff that names `Foo.nim` while the graph holds `foo.nim` silently drops the affected test from the selection — an unsound miss, the one failure mode crisol exists to prevent.
- **The string type is lying.** `HashSet[string]`/`Table[string, …]` keyed on paths compiles and runs and is wrong; the bug is invisible until a second spelling appears. A distinct `TrackedPath` with no implicit `string` conversion makes every un-canonicalized comparison a compile error — the same "make the illegal state unrepresentable" move RFC-0007 made with `ChildId` and `LimitKind`.

## Identity check

crisol is "one layer up" from the test and its value is sound *selection* and trustworthy results (MEMORY → boundary-granularity-discriminator, crisol-value-is-selection). Path identity is a **soundness property of selection and of the cache key** — squarely identity, not mechanism. Nothing here reaches inside a test binary or changes what crisol enforces; it makes the set-membership and key-equality that selection and caching already perform *correct across platforms and across roots*. The case-fold **policy** is a capability (probed per root, degraded, reported), exactly as RFC-0007 treats kill-domain strength and limits. Root-tagging is the same move applied to *where* a path lives: an attestable, portable fact derived from configuration, not a machine-local absolute string.

## Load-bearing property

> **One file, two spellings, one identity — end-to-end through the real entry point.** On a case-insensitive volume, running `crisol run --changed <diff>` where the diff names a source in a different case and/or separator convention than the on-disk / dep-graph spelling selects the affected entrypoint **exactly once**. Proven on the `windows-latest` leg (native case-insensitive NTFS) *and* the existing case-insensitive `macos-latest` APFS leg, driving the real `crisol` binary — not a unit test over the canonicalizer in isolation.
>
> The cache half of this property is **not** "a warm entry hits across spellings" — that would require folding the key, which is unsound (below). It is instead: **the same tree produces the same cache key on every host and every run**, regardless of that host's case-sensitivity — not because discovery walks the disk deterministically (closure membership is compiler-manifest/import-origin — `resolveMangledAll`, depfiles, `cc -M` — and two files importing one dependency under different case genuinely can put two spellings of the same file into the same closure, on any host, on any run) but because every manifest-origin spelling is already reduced to Nim's own **on-disk real case** before a key is ever built (§4 — established empirically by `A0-spike`): a dependency has exactly one recorded spelling per committed tree, independent of importer case or import order, never whichever spelling a given compiler pass happened to resolve first. That spelling is a pure fact of the committed tree — identical on every host and every run that checks out the same commit. Portability and never-wrong-hit, not warm-hit-under-drift.
>
> `A3b-ii` is the first slice that proves the *selection* half live, end-to-end (`A3b-i` wires the diff-ingest plumbing as far as narrow's door but does not yet retype narrow's own membership test, so it does not yet prove fold live). `A0`–`A3a-i` are honest, enumerated prerequisites, not proofs of the property themselves: `A1` is a pure leaf with no consumer yet; `A3a-i` gives `Entrypoint` type uniformity (a `tp: TrackedPath` field that agrees with `path: string`) but proves nothing about fold, because `discover`'s dedup set has exactly one on-disk spelling per file — `walkDir` never produces a second spelling to fold against (entrypoints genuinely are the one case in this RFC where "one on-disk spelling per file" holds; closure members are not, §4). If the selection half cannot be shown live from `A3b-ii` — mixed-case diff in, single correct selection out — the abstraction is scaffolding around a hole.
>
> The CACHE half is dark from `A1` through `A5c` **by design**, and honestly declared as such (round-3, R3-13): the cache-portability payoff — the SAME tree producing the SAME key on every host and every run (§4, established by `A0-spike`'s on-disk-canonicalization result) — is not asserted end-to-end until `A5c`'s extended fixture (Stages & slices). `A0`'s golden vectors are the interim regression net across that span (they prove Linux stays byte-identical slice over slice), not a liveness proof of cross-host portability itself. This is a defensible, declared deferral rather than a silent gap: `A5a`–`A5c` are consecutive slices, so the dark window is short and closes before `A-final`.

The producer is the entry-boundary reducer (`classify`) plus the retrofit of the closure/dep-graph/cache membership to `TrackedPath`; the property is dark until *both* the diff-ingest path and the dep-graph both canonicalize through it. A consumer (`HashSet[TrackedPath]`) without its producer (diff paths reduced through the same boundary) is forbidden — `A3b` (`A3b-i` + `A3b-ii`) wires the whole path from `--changed` ingest to selection, then the ladder hardens the rest of the surfaces.

## Non-goals

- **Not inode/file-id identity.** crisol never uses `stat` device+inode or `GetFileInformationByHandle` file-id as the identity: it is volume-local (un-portable into the attested cache wire), undefined for not-yet-existing paths, and unstable across the copy/restore a distributed cache implies. Symlink *resolution* stays exactly where `closure.nim` already does it (realpath at closure-extraction time); this RFC does not add link-following to the identity function.
- **Not a virtual filesystem or path-remapping layer.** No `--noAbsolutePaths` replacement, no build-root rewriting — RFC-0009 canonicalizes and tags spellings, it does not relocate files.
- **Not Windows-correct compile *measurement*.** ccache detection (`compilereport.detectAmbientCcache`, hard-coded `cc`/`gcc`), the `cc -M` header probe (`ccprobe.parseCcMDeps`, gcc/Make-shaped), and `artifactid.eraseKnownString`'s `/`-anchored known-string guard, alongside `artifactid.includeClosureContentHash` (`artifactid.nim:293`), stay Linux-shaped for now — named here explicitly so `A-final`'s grep-gate allowlist is derivable straight from this RFC rather than invented ad hoc at sweep time. RFC-0006 (the measurement RFC) is parked on a negative benchmark; making measurement Windows-correct is its concern, not this RFC's.
- **Not new platform backends.** Windows/darwin process backends are RFC-0007's; this RFC only makes the suite compile and the identity fold correctly on them.
- **Not `report.nim`'s `CRISOL_SINK` child-I/O channel.** `report.nim:65`'s sink is pure child-process output plumbing, not a path identity — named here explicitly (round-3, R3-25) so the `A-final` grep-gate allowlist is derivable straight from this RFC's Non-goals rather than invented ad hoc at sweep time, matching the posture already taken for `compilereport`/`ccprobe`/`artifactid` above.
- **Not an arbitrary-workspace multi-root system.** `TrackedRoots` is exactly `{project, deps}` — the roots crisol already recognizes (`projectRoot`, configured `depRoot`s). This RFC does not generalize to N unrelated workspace roots.

## Design

### 1. `TrackedPath` — identity separated from spelling, tagged to its root

The terrain survey shows two fatal conflations: crisol uses **one** `string` both as the thing it *opens* (needs real case, OS separators, absolute) and as the thing it *compares and hashes* (needs a canonical, case-folded, portable form) — and it uses **one implicit root** (project-relative) for identity that in reality spans several roots. `TrackedPath` splits both:

```nim
## paths.nim — the ONLY module that constructs or interprets path identity.

type
  RootTag* = distinct uint16
    ## Which tracked root a path is relative to. 0 = project; 1..N = configured
    ## dep roots, assigned in declared/discovered order — stable for a given
    ## config, never recomputed from a path string. Borrowed `==`/`hash` only
    ## — deliberately NO serialization proc (below): a RootTag's numeric value
    ## never escapes this process. Anything persisted is addressed by the
    ## root's configured NAME instead (round-2; round 1 persisted the ordinal
    ## directly, which silently pointed at the wrong root the instant a dep
    ## root was added, removed, or reordered in config).
  `==`*(a, b: RootTag): bool {.borrow.}
  hash*(t: RootTag): Hash {.borrow.}

  FoldPolicy* = enum fpNone, fpAsciiLower   ## round 1: ASCII only (see Risks)

  TrackedPath* = object
    ## crisol's canonical identity of a file tracked under SOME root — project
    ## or a dep root. Constructed only via `classify` (§2), `fromCanonical`,
    ## or `fromJson` (already-canonical input); every equality, membership,
    ## dedup, ordering, and cache-key input in the system is over TrackedPath,
    ## never a bare string. All fields private: a public `rel` field
    ## would let `TrackedPath(rel: x)` counterfeit an identity with no
    ## fold ever applied.
    rootTag: RootTag
    fold: FoldPolicy   ## the matched root's OWN probed policy at construction
                       ## time (§3) — a POLICY, not a derived folded string:
                       ## `==`/`hash` fold `rel` on the fly, one pass,
                       ## from this field (round-2; round 1 stored a derived
                       ## `ident` string alongside `rel` — twice the
                       ## memory on a large graph, and a value that could go
                       ## stale relative to a later probe if ever mishandled).
    rel: string        ## real-case, forward-slash, root-relative spelling —
                       ## the STORED identity field (round-3 rename, R3-22:
                       ## round-2's `display` name carried three roles at
                       ## once — presentation, an openable-path seed, and the
                       ## raw key bytes — and a name read as "presentation"
                       ## invites a log-cosmetics edit that reshapes cache
                       ## keys fleet-wide; `rel` names it for what it is).
                       ## What humans see (`display(tp)`/`$tp`, below) and
                       ## what `toNative(tp, roots)` re-expands to
                       ## open/spawn. On rootTag 0, a case-sensitive volume,
                       ## this is EXACTLY today's toProjectRelative output —
                       ## nothing changes. A manifest-origin `rel` is always
                       ## Nim's ON-DISK real case: Nim canonicalizes module
                       ## identity to the on-disk spelling before the manifest
                       ## is emitted, so one dependency has exactly one
                       ## spelling per committed tree (§4, A0-spike) — never
                       ## an arbitrary first-seen or case-variant spelling.

  PathClassKind* = enum pcTracked, pcOutside
  PathClass* = object
    ## The TOTAL result of classifying a native path (§2). Every native
    ## spelling lands in exactly one arm — there is no refusal here. TWO
    ## arms, not three: `tp.rootTag` already answers project-vs-dep, so a
    ## separate "which dep root" arm would restate it — a representable
    ## illegal state (round-2; round 1 shipped three arms).
    case kind*: PathClassKind
    of pcTracked: tp*: TrackedPath   ## safe to expose: uncounterfeitable (above).
    of pcOutside: native*: NativeAbs

  NativeAbs* = object
    ## A native-absolute path that is not (yet, or ever) known to be under
    ## any tracked root: a milpa CAS symlink target, a stdlib/nimble header
    ## reached via `cc -M`, or any candidate BEFORE `classify` has run.
    ## Distinct from TrackedPath by construction: it carries no root tag and
    ## can never feed a cache key. Native-canonicalized (§2) but NOT
    ## fold-policy-reduced. Private field — it is a Table key in
    ## `SourceIndex` (A4a) and is read for exclusion logging, so it needs its
    ## own `==`/`hash`/`path()` rather than exposing the raw string.
    abs: string
  proc path*(n: NativeAbs): string = n.abs
  proc `$`*(n: NativeAbs): string = n.abs
  proc `==`*(a, b: NativeAbs): bool = a.abs == b.abs
  proc hash*(n: NativeAbs): Hash = hash(n.abs)

  NativeRoot* = object
    ## One tracked root's native, absolute location and its own probed
    ## identity capability — computed ONCE (§2, config.nim) and threaded,
    ## never re-derived downstream. Private fields + accessors, matching
    ## NativeAbs/TrackedPath's discipline (round-1 left these public-mutable
    ## — inconsistent with the rest of the type's counterfeit-proofing).
    abs: string          ## native-canonicalized (§2) absolute path.
    realAbs: string       ## `expandFilename`'d once at construction — the
                          ## realpath form, so a symlinked root (this
                          ## project's own milpa CAS layout) still matches a
                          ## realpath-expanded candidate at classify time
                          ## (§2; round-2 fix for an under-selection hole).
    foldPolicy: FoldPolicy ## probed for THIS root's volume (§3) — each
                          ## NativeRoot answers for itself; a dep root on a
                          ## different-sensitivity volume than the project
                          ## root folds correctly under its OWN policy.
    name: string          ## configured name ("" for the project root) — the
                          ## ONLY thing ever persisted to identify a root
                          ## (RootTag, above); validated at config time to
                          ## contain neither `/` nor `:` (closing a keyBytes
                          ## grammar collision, §4).
  proc foldPolicy*(r: NativeRoot): FoldPolicy = r.foldPolicy
  proc name*(r: NativeRoot): string = r.name
    ## `abs`/`realAbs` are deliberately NOT exported as accessors (round-3,
    ## R3-28): a public raw-path getter invites exactly the raw `startsWith`
    ## comparison `A-final`'s grep-gate exists to flag. `classify` (§2, same
    ## module) reads the private fields directly; nothing outside `paths.nim`
    ## needs the native root path itself — only its fold policy and name.

  TrackedRoots* = object
    ## Immutable once constructed (round-2: round 1's sketch left foldPolicy
    ## mutable and lazily probed on what is a value type — incoherent, since
    ## a mutation to one copy would not propagate to another, and `==`/`hash`
    ## would then depend on how many comparisons had already run before the
    ## first probe fired). PRIVATE fields (round-3, R3-5): a public `deps`
    ## broke the counterfeit-proofing every other type in this family got —
    ## `RootTag` is POSITIONAL (above), so a `var` reorder of a public `deps`
    ## silently re-tags every path through the front door, the exact
    ## wrong-root bug name-persistence exists to prevent. Accessors below;
    ## construction only via `initTrackedRoots`. Same-module `classify`
    ## needs no accessors — it reads the private fields directly.
    fproject: NativeRoot    ## rootTag 0.
    fdeps: seq[NativeRoot]  ## rootTag 1..deps.len, by configured name/order.
  proc project*(r: TrackedRoots): lent NativeRoot = r.fproject
  proc deps*(r: TrackedRoots): lent seq[NativeRoot] = r.fdeps

  CacheKeyPath* = distinct string
    ## keyBytes' return type (§4): canonical, UNFOLDED cache-key bytes. A
    ## distinct type, not `string`, so `identityKey`/`planner.slug`/
    ## `cachelocalfs.sidecarPath`/`fnv.chainedContentHash` cannot accept a
    ## bare `rel` by accident — the same "make the illegal state
    ## unrepresentable" move extended to the one place a leak is worst: the
    ## attested wire. `string(k)` is the sole, explicit escape hatch, used
    ## only where something must actually write the bytes out.

proc initTrackedRoots*(projectNative: string;
                        deps: seq[tuple[name, native: string]];
                        stateDir: string;
                        probe: proc (rootAbs, stateDir: string): FoldPolicy =
                          probeFoldPolicy): TrackedRoots
  ## Builds project + each dep NativeRoot, probing EAGERLY here — not lazily
  ## on first comparison — backed by a per-process memo keyed by canonical
  ## root abs path, so the hundreds of Config constructions a test run
  ## performs pay the probe cost once per distinct root, not once per Config.
  ## `probe` is injectable (§3): a test fixes a FoldPolicy directly, no
  ## Windows round-trip required to exercise fold semantics on Linux CI.
  ## Round-3 fix (R3-6): round-2's signature named a `NativeRootSpec` type
  ## that was used here but defined nowhere, and took no `stateDir`, making
  ## the default `probeFoldPolicy` (§3, which needs one) uninvokable.
  ## `NativeRootSpec` is dropped — the pre-boundary shape is a raw string
  ## per §2, so a transparent `tuple[name, native: string]` says exactly
  ## that, with no opaque accessor object to define or maintain.

proc display*(tp: TrackedPath): string = tp.rel
proc `$`*(tp: TrackedPath): string = tp.rel          ## logs/errors: real case
proc isProject*(tp: TrackedPath): bool = tp.rootTag == RootTag(0)
proc `==`*(a, b: TrackedPath): bool =
  a.rootTag == b.rootTag and fold(a.rel, a.fold) == fold(b.rel, b.fold)
  ## FOLDED, computed on the fly from the stored POLICY — selection soundness.
  ## Invariant (round-3, R3-21): same `rootTag` ⇒ same `fold` policy within
  ## one process — two `TrackedPath`s sharing a root were built from the
  ## same `TrackedRoots`, which probes each root's policy exactly once.
  ## Debug-asserts `a.fold == b.fold` whenever `a.rootTag == b.rootTag`: a
  ## mismatch here is a cross-policy comparison bug (a test fixture built
  ## under a different policy than the roots it is compared against), not a
  ## legitimate case — round-2's asymmetric folding (each side folded by its
  ## own stored policy) silently MASKED exactly this violation instead of
  ## catching it.
proc hash*(tp: TrackedPath): Hash = ...                   ## over (rootTag, folded rel)
proc keyBytes*(tp: TrackedPath; roots: TrackedRoots): CacheKeyPath =
  ## Canonical, UNFOLDED cache-key bytes (§4) — NEVER the same accessor as
  ## `==`/`hash`. Takes `roots` (round-3, R3-4: round-2's `keyBytes(tp)`
  ## could not produce its own documented output — a dep-root member's
  ## `dep:<name>/rel` form needs the tagged root's configured NAME, which
  ## lives in `NativeRoot`, reachable only via `TrackedRoots`; `TrackedPath`
  ## itself stores only `rootTag`/`fold`/`rel`). The uniform module rule,
  ## stated once here: comparison (`==`/`hash`) is CONTEXT-FREE; every
  ## conversion OUT of identity (`toNative`, `toJson`, `keyBytes`) TAKES
  ## `roots`. All named `keyBytes` consumers already hold a `Config`
  ## (→ `roots`). rootTag 0 (project) prefixes NOTHING: keyBytes == rel, so
  ## a single-root project's Linux keys are bit-identical to today's bare
  ## path string. rootTag N>0 (a dep root) prefixes the root's configured
  ## NAME, e.g. "dep:mydep/src/foo.nim" — portable by construction, no
  ## machine-local absolute path ever reaches a key again.

proc cmpKeyBytes*(a, b: TrackedPath; roots: TrackedRoots): int =
  ## The SOLE ordering over `TrackedPath` (round-3, R3-3): total, over raw
  ## UNFOLDED `keyBytes` bytes — never over the folded form `==`/`hash` use.
  ## No public `<` exists: a bare `sort()` over `seq[TrackedPath]` is a
  ## compile error, defusing the whole class of unowned sort sites that
  ## would otherwise resolve to a folded, unstable order the instant a
  ## fold-equivalence class has more than one raw `rel` member — round-2's
  ## `<` restated a "never sort to a key/wire" comment at three separate
  ## call sites and a consistency-with-`==` rationale that Nim's `sort`
  ## never actually consults; round-3 deletes the footgun instead of
  ## re-documenting it. Every sort site in the system (depgraph closure
  ## array / header order, the `chainedContentHash` pairing order,
  ## `planner`'s staleness re-hash) calls this, never a derived `<`.

proc classify*(native: string; roots: TrackedRoots): PathClass
```

State invariants: `rel` is non-empty and carries no leading or trailing `/`, except the `pcOutside` root-itself edge case, which is not a `TrackedPath` at all (§2: a tracked root's own directory classifies `pcOutside`, since it is a container, not a trackable file — resolving what would otherwise be a collision between the non-empty-`rel` invariant and `classify`'s totality). No implicit `string` conversion exists anywhere, so every un-reduced comparison that survives the migration is a **compile error**, not a latent Windows bug — this is `ChildId`/`LimitKind`'s "make the illegal state unrepresentable" (RFC-0007 §1) applied to paths, now extended to the cache-key boundary too via `CacheKeyPath`. (`fold(s, policy)` is a private helper — identity under `fpNone`, ASCII-lowercase under `fpAsciiLower` — not itself part of the public interface below.)

Two constructors, for the two shapes native input actually arrives in: `classify(native, roots)` is total (§2) — it is how a raw OS-native string (a `walkDir` result, a `cc -M` header path) becomes identity, or is decided to be outside every tracked root. `fromCanonical` is for input that is *already* canonical relative form — a persisted `rel` read back from the dep graph, a `git diff` path — it validates the shape invariant (rejecting a leading `\`, any `.`/`..` segment, an absolute form — drive letter, UNC, or leading `/` — and a doubled separator: all signs the caller handed it un-reduced native text rather than already-canonical relative text), applies the tagged root's fold policy, and critically **never touches cwd**: the bug this replaces (round-1 finding) absolutized step 1 of the old `toProjectPath` against the process's current working directory, which is silently wrong the moment cwd isn't the root. A third input shape exists and is neither of these: user-origin RELATIVE native text (a quarantine KDL value, a CLI argv entry, a `gskFiles` glob selector) that is relative but not yet reduced — round 1 had no answer for it, which would have reopened `fromCanonical` as an implicit fourth constructor over unvalidated text. Round 2's answer: such text is joined against an EXPLICIT base (`projectRoot` for a KDL value, the process's own captured cwd for a CLI argv entry — captured once, at the call site that owns it, never inside the identity layer itself) and routed through `classify`, never `fromCanonical`. A glob selector's own matching folds under the matched root's policy too (a case-variant glob must not silently match nothing on an insensitive volume). `toNative(tp, roots)` is the sole inverse, mirroring `classify`'s argument order (subject first, roots second) rather than the flipped order an earlier draft had.

Deep module: `paths.nim`'s identity-comparison interface is `classify`, `tracked`, `isProject`, `fromCanonical` (two arities), `fromJson`, `toNative`, `toJson`, `==`, `hash`, `cmpKeyBytes`, `keyBytes`, `display`, `$` — fourteen entry points (recounted at round-3 edit time; the count is unchanged by the `A0-spike` reshape, which removes only a separate merging-container surface, §4 — never itself part of this count) hiding drive-letter/UNC/separator/case-fold reduction, root classification and tagging, deterministic key derivation, and the `\\?\` long-path concern. (Round-3: `<` is deleted outright — R3-3 — no public ordering exists except `cmpKeyBytes`, total over unfolded `keyBytes`.) `nativeCanonicalize` (§2), `probeFoldPolicy` (§3), and `initTrackedRoots` (above) are exported from the same module but belong to the boundary-reduction, capability-probe, and root-construction layers respectively — not the comparison interface proper. Callers never see any of the reduction itself, only these names.

### 2. One entry boundary — `classify`, and the total classification

Every native spelling enters identity through exactly one reducer, replacing the ad-hoc `absolutePath.normalizedPath` recomputed at 15+ sites (round-1 terrain survey):

```nim
proc nativeCanonicalize*(native: string; base: string): NativeAbs =
  ## Steps 1-2 of the reduction, factored out and applied UNIFORMLY to every
  ## native-absolute path entering SourceIndex/underAnyRoot — not only to
  ## eventual tracked members (fixes the round-1 finding that native-side
  ## gates stayed case-sensitive upstream of the type, silently dropping a
  ## candidate before identity ever saw it):
  ##   1. if `native` is relative, join against `base` — `base` MUST already
  ##      be absolute and canonical; this proc NEVER reads the process cwd
  ##      itself (round-2 fix: round 1's `absolutePath` call inside this
  ##      layer silently resolved against whatever cwd happened to be
  ##      current — the exact bug §1 calls out for the old `toProjectPath`,
  ##      and the same one that let `cc -M`'s relative header paths resolve
  ##      against the wrong directory, `closure.nim:1375`). The one
  ##      legitimate cwd read in the whole retrofit (a CLI argv path's base)
  ##      is captured ONCE, by the call site that owns it, and passed in.
  ##   2. absolutePath + normalizedPath (`.`/`..`, redundant separators)
  ##   3. drive-letter case + UNC canonicalization; strip a leading `\\?\`
  ##      or `\\?\UNC\` prefix (re-added only by `toNative`, when a path
  ##      needs it — §Risks); `\` -> `/`
  ## NativeRoot.abs/.realAbs are reduced through this SAME function at
  ## construction (§ config.nim, below) — otherwise a `\\?\`-prefixed root
  ## never prefix-matches a walked path that lacks the prefix.

proc classify*(native: string; roots: TrackedRoots): PathClass =
  ## TOTAL: every native spelling classifies. Nothing is refused HERE.
  ##   1. na := nativeCanonicalize(native, roots.project.abs)
  ##   2. PROJECT FIRST: component-boundary match `na` against
  ##      roots.project.abs AND roots.project.realAbs — `na == root` (the
  ##      root itself; not trackable, step 5) or `na.startsWith(root & "/")`
  ##      (a genuine path-COMPONENT boundary, never a raw startsWith, which
  ##      would wrongly match a sibling directory that merely shares the
  ##      root's name as a prefix, e.g. `/proj-extra` against root `/proj`).
  ##      A path under the project root is ALWAYS tag 0 — even one that also
  ##      nests under a configured dep root's own directory (a vendored dep
  ##      checked into the project tree) — matching git's own view and
  ##      keeping `fromCanonical`'s tag-0 shorthand meaningful for the
  ##      common case.
  ##   3. else, the same component-boundary match against each dep root's
  ##      `.abs` and `.realAbs` (longest match wins on overlap); a symlinked
  ##      dep root (this project's own milpa CAS layout) matches via
  ##      `.realAbs` even when the candidate reached identity through its
  ##      real path rather than its lexical one (round-2 fix — round 1
  ##      matched only the lexical form and silently dropped such
  ##      candidates as under-selection, §Risks).
  ##   4. matched -> relativize, separators -> '/', fold under the matched
  ##      root's own probed FoldPolicy -> PathClass.pcTracked(tp)
  ##   5. no match, OR `na` equals a root's own directory exactly (the root
  ##      itself is a container, never a trackable file) -> PathClass.pcOutside(na)
```

The classification is total and *never throws* — attribution is a decision each call site makes about the `PathClass` it receives, not something the boundary imposes uniformly. This preserves two behaviors the round-1 draft's "refuse if not under root" contradicted outright: `closure.nim`'s existing silent `continue` for out-of-all-roots candidates (`closure.nim:1208`, `:1378` — stdlib/nimble headers reached via `cc -M`, which are legitimately outside every tracked root and must not abort the walk) stays exactly that, a call site pattern-matching `pcOutside` and excluding; `cekEnvironment`'s fail-closed refusal is for a narrower thing — an *unattributable manifest shape* (a non-absolute `{.link.}`, a tuple `{.compile.}` entry that carries no path at all) — and that refusal is preserved verbatim as its own call site's choice, not folded into the boundary. Making out-of-root a hard refuse at the boundary itself would break every depRoot closure and every stdlib depfile — both currently, correctly, land `pcOutside`.

`TrackedRoots` is computed **once** in `config.nim`, via `initTrackedRoots` (§1), at `projectRoot`'s three origins (explicit KDL, git-root, cwd) and each configured dep root, with the fold policy probed EAGERLY there per root (§3) and threaded down — killing every downstream re-derivation. `discover.nim:306`'s verbatim-use and the 15+ `projectRoot.absolutePath.normalizedPath` recomputations (closure/depgraph/runner/cacheregistry) all collapse to "trust the `TrackedRoots` you were handed."

`toNative(tp, roots)` is the inverse for I/O: the tagged root's native abs path, joined with `tp.display` in OS-native separators — the only way to turn an identity back into something openable/spawnable. The compiler cwd (`runner.nim` `ChildSpec.cwd`) and file re-opens for staleness (`depgraph` `isEntryStale`) go through it. Comparison itself needs no root at all: `==`/`hash` (§1) read only the `TrackedPath`'s own stored `rootTag`+`fold`+`rel` — construction is the only place `TrackedRoots` must be threaded (~20-30 sites that already thread a root today; net-zero ceremony over the status quo). Worth stating plainly: **comparison is context-free, construction is explicit.** `SourceIndex` (A4a) gets its own `tracked(index, native): Option[TrackedPath]` forwarder so closure's hot call sites thread the index alone, not the index and `TrackedRoots` both.

### 3. Case-fold is a probed, per-root capability, not a `#define`

Case sensitivity is a property of the **volume**, not the OS: a default NTFS volume and a default APFS volume are case-insensitive; a Windows directory with the per-dir case-sensitivity flag, or a case-sensitive APFS volume, is not; Linux is case-sensitive except on a mounted case-insensitive FS; and a project root and a dep root can legitimately sit on *different* volumes. So the fold policy is probed **per `NativeRoot`**, not once per run — exactly the RFC-0007 posture (probe once, degrade, report), applied per-capability-instance:

```nim
proc probeFoldPolicy*(rootAbs: string; stateDir: string): FoldPolicy =
  ## 1. OS QUERY FIRST (authoritative; rarely fails; NEVER touches disk):
  ##      Windows: FileCaseSensitiveInformation (the per-directory NTFS flag)
  ##      macOS:   pathconf(rootAbs, _PC_CASE_SENSITIVE)
  ##      Linux:   an ioctl FS_IOC_GETFLAGS casefold-bit check (ext4/F2FS
  ##               casefold) or a statfs(rootAbs) filesystem-type check for
  ##               a known-case-sensitive type — answers fpNone for a plain
  ##               ext4 mount, crisol's daily toolchain, WITHOUT ever
  ##               touching disk (round-2: round 1 had every Linux run fall
  ##               through to step 3 below, which requires WRITE access even
  ##               to answer "case-sensitive" — wrong for a read-only dep
  ##               root, §Risks).
  ## 2. READ-ONLY FALLBACK on query failure: if `rootAbs` already contains
  ##    at least one directory entry, stat it under a case-flipped spelling
  ##    of its own name. No write, no create/stat race window, and answers
  ##    definitively without ever requiring write access — the case a
  ##    read-only milpa CAS dep root needs.
  ## 3. CREATE-AND-STAT, only if (1) is unsupported and (2) found no entry
  ##    to test against (an empty root): a probe-file pair whose name
  ##    carries a per-PROCESS-unique suffix — never a fixed name, which
  ##    would race a concurrent run's create/stat window into a false
  ##    case-sensitive read. Housed in `stateDir` IFF stateDir is on the
  ##    same volume as `rootAbs` (CRISOL_STATE_DIR may redirect to a
  ##    different volume, which would answer for the wrong one); otherwise
  ##    an ignored dot-name file directly in `rootAbs`, removed after. This
  ##    is the only step that needs write access, and it is now the LAST
  ##    resort, not the only path.
  ## Probed EAGERLY at TrackedRoots construction (§1, initTrackedRoots),
  ## memoized per-process by canonical root abs path — Config is built
  ## hundreds of times across the test suite, so the probe is a per-process,
  ## per-root cost paid once, never once per Config construction.
```

`FoldPolicy` is **injectable** past the probe: a `NativeRoot`/`TrackedRoots` value can carry a directly-set `foldPolicy`, bypassing `probeFoldPolicy` entirely, so fold semantics are unit-testable on Linux CI without a Windows round-trip. `fold(s, fpNone) == s`, so **Linux is byte-for-byte unchanged** and RFC-0005's attested wire is untouched there; `fpAsciiLower` lowercases ASCII `A–Z` only (round 1 deliberately ASCII-only — §Risks — the OS's own case tables are locale- and version-dependent, and a full-Unicode fold that disagrees with the kernel's table would *reintroduce* the split it exists to prevent). Each root's policy is reported in the run's evidence alongside the other capabilities (the `jsonout` schema revision this lands under is named at `A2`).

When the OS query genuinely fails **and** the read-only and create-and-stat fallbacks also genuinely fail (an empty, permission-denied root on both the state dir and the root itself, say) — a materially rarer double failure now than round 1's create-and-stat-only path — the run degrades on **both** axes rather than silently picking a fold pole: `--changed` falls back to a full run (sound over-selection, the same posture RFC-0007 already uses for an absent dep graph) and the cache is bypassed for that run, store and read alike (sound: cold, never wrong). Comparisons made during such a run use **fpNone** — never a fold, which never aliases two genuinely distinct files, the conservative direction — and because the same run is already a forced full run, `fpNone`'s own under-fold risk never reaches a selection decision it could get wrong. The resulting dep graph is **not persisted** (or, if a header write is already underway, is marked degraded and unconditionally discarded on the next load, §4) — a graph built under an unresolved policy must never be silently trusted by a later, healthy run. `rootInsideStateDir` (§4) fails **closed**, not open, when no policy was obtained. This is reported in evidence, never silent — the membership consumer and the key consumer have *opposite* safe directions on an ambiguous policy, so no single silent default serves both.

### 4. The cache key reads `keyBytes` — never folded, and is deterministic by construction

Two axes of the same `TrackedPath`, deliberately kept separate (Fork C):

- `==`/`hash`, in-memory membership/lookup/dedup, and native-side closure gates **fold**, under the tagged root's probed policy — this is what makes selection sound on a case-insensitive volume.
- `keyBytes` — the sole input to `keys.identityKey`/`soundnessKey`, `planner.slug`, `cachelocalfs.sidecarPath`, and `fnv.chainedContentHash` — **never folds**. It is always the unfolded, rootTag-qualified `rel`, returned as a `CacheKeyPath` (§1) so a bare `rel`/`string` cannot reach a key call by accident.

This is not a compromise; it is the only sound choice once the actual variable is named. `walkDir` produces `discover`'s ENTRYPOINTS, not closure MEMBERS: a closure member's spelling comes from compiler-manifest/import-origin data — `resolveMangledAll`'s `@m`/`@p`/`@n` decode, a `cc -M` depfile line, `analyzeManifest`'s `{.compile.}`/`{.link.}` entries — each carrying whatever case the *importing* source file's own `import` statement (or the toolchain's own header search) happened to spell. The premise this RFC shipped in round 1 — that closure/dep-graph membership derives from a deterministic on-disk walk, so keys are automatically host- and run-stable — is FALSE for exactly this reason: two files that `import Foo` and `import foo` for the same on-disk dependency could, in principle, each contribute their own manifest-origin spelling of one file to the same closure, and an unfolded `keyBytes` built from whichever spelling manifest-resolution order happened to produce would quietly differ across otherwise-identical runs — falsifying the load-bearing property's cache half outright.

**`A0-spike` tested whether that theoretical variance ever reaches a real manifest, and it does not (round-3 R3-1, RESOLVED 2026-09-11).** Measured directly on both case-insensitive legs (`macos-latest` APFS + `windows-latest` NTFS, CI runs 34567534296 and 34570358383, all legs green): Nim 2.2.10 UNIFIES two differently-cased importers of one on-disk dependency into a SINGLE `@m` manifest entry, and the recorded spelling is ALWAYS the **on-disk real case** — independent of importer case (an upper-only `import Widget` of an on-disk `widget.nim` still records `widget.nim`) and of import order (lower-first and upper-first agree). A dependency therefore has exactly ONE recorded spelling per committed tree — a fact of that tree (which files exist, at what on-disk case), identical on every host and every run that checks out the same commit — established empirically by `A0-spike` and permanently guarded by `tests/conformance/test_spike_import_case.nim`: if a future Nim ever records the import spelling instead of the on-disk one, it fails and this decision reopens.

`keyBytes` is deterministic **by construction** on that basis alone: there is no fold-class collision between manifest-origin spellings of one dependency for anything to resolve, so no representative-selection rule is needed to resolve one. This keeps identity purely textual — no filesystem case-query, no `stat`, nothing that touches disk beyond Nim's own manifest resolution — honoring the **locked** "textual, not inode" non-goal. `A3c`'s persisted-record assertion is correspondingly direct: not "the record matches the real on-disk case" as a comparison against some independently-queried truth, but "the record IS the on-disk case Nim itself resolved, byte-identical across a cold rebuild and a warm load of the same tree" — still a strong anti-dark determinism assert, just one now satisfied by a fact of the toolchain rather than a merge rule. (Two alternatives once considered for this same gap — a filesystem case-query at classify time ("Option A") and a textual canonical-representative merge ("Option B") — are recorded, and both superseded by this result, in Alternatives considered, below.)

`canonicalMerge`/`CanonicalSet` — the merge machinery Option B would have required — are accordingly REMOVED from §1's type surface, §4, and slices `A1`/`A3c-ii`/`A4a`/`A4b`/`A5c`/`A-final`, superseding every prior mention of them below (the persisted-graph order-dependence sub-case is closed too — the recorded spelling is order-independent, so a warm-load spelling can never drift from a cold-rebuild spelling). `A4b`'s cold-vs-warm determinism assertion still stands as the live proof, now proving on-disk-case determinism rather than a textual merge.

On a case-sensitive, single-root (rootTag 0) project, `keyBytes == rel == today's bare string` — every existing Linux cache/ledger/attestation key is bit-identical, no wire migration, no fleet-wide invalidation (the RFC-0005 constraint). `foldPolicy` per root is persisted in the depgraph header — keyed by the root's configured NAME (§1/§2; never the in-memory `RootTag` ordinal, which is not stable across a config edit) — alongside `nimVersion` (`depgraph.nim:152`); a mismatch between the header's persisted policy for a name and the current probe for that same name discards the graph as absent rather than comparing across policies. **This is explicitly NOT cache/ledger version material** — it gates only "is this depgraph file's own entry table still valid to read," never "is this cache entry valid to share": a `fpNone` Linux host and an `fpAsciiLower` Windows host attesting the identical tree must produce identical version material and identical `keyBytes` (per Fork C, keys never fold), or the fleet-portability this section's whole determinism argument establishes would be false by its own construction.

`fnv.chainedContentHash` currently takes one string for two jobs — chaining the hash *and* opening the file (`fnv.nim:41-74`) — which breaks the instant `keyBytes` and the openable path diverge (a dep-root member's `keyBytes` is `dep:name/rel`, not something `readFile` can open directly). It is reworked to take pairs: `keyBytes` feeds the chain, **sorted by `cmpKeyBytes`, never by any folded order** (round-3: no `<` exists at all, R3-3 — `cmpKeyBytes` is total over raw, unfolded bytes and is the only order this RFC ever allows to reach a key, a sort, or the wire, a global invariant, not just this one call site's rule; round-2's now-deleted `<` was defined over the *folded* form for in-memory consistency with `==`, so two distinct-`rel` members of one fold class would have compared equal under it and sorted unstably into a persisted, wire-facing order). The paired native path (`toNative(tp, roots)`) is what actually gets opened. `planner.slug` derives its **whole** slug — the human-readable prefix as well as the hash — from `keyBytes`; a previous approach that hashed the folded form but kept an unfolded prefix would let the same hash disagree with its own directory name. `rootInsideStateDir` (`cacheregistry.nim:392`) is routed through folded identity rather than a raw `startsWith`, fixing a fail-*open* on the RFC-0005 fail-closed check — and fails **closed** (§3) when a degraded run has no policy to consult at all. Dep-root NAMEs are validated at config time (no `/`, no `:`). **The `dep:*` collision is pinned as an ESCAPE at the `keyBytes` boundary, not a name-side rejection (round-3, R3-20):** a tag-0 directory literally named `dep:foo` is legal on ext4, and `classify` is total, so `dep:foo/x.nim` lands `pcTracked` tag 0 whether or not any config validation runs — a name-side guard cannot see a future `rel` it never inspects. The actual fix: `keyBytes` for tag 0 prefixes `./` IFF the `rel`'s first path segment matches `dep:[^/:]+` — injective (nothing else begins `./`: `fromCanonical` rejects a leading `.` segment, and a dep key begins `dep:` not `./`) and CONDITIONAL, so an ordinary Linux key stays bit-identical (the RFC-0005 constraint). The identical escape governs the `ClosureEntry.closure` CLI wire (`A3d-iv`).

### 5. What stays exactly as it is

- **Symlink/realpath duality** (`closure.nim` `IndexedFile.lexical`/`.real`, the C1a ambient-symlink `expandFilename` fallback) is untouched: `classify` and the native-canonicalizer layer case/separator identity *underneath* the existing lexical-vs-real machinery, they do not add link-following to identity (Non-goals). `NativeRoot.realAbs` (§2) matching a realpath-expanded candidate at the ROOT level is a different, narrower fix — it keeps a symlinked dep root's own children classifiable — and does not change how `closure.nim` itself decides lexical vs. real for an individual member.
- **The fail-closed refusal** of stripped/unattributable manifest entries (`closure.nim` `cekEnvironment`) is preserved verbatim, as its own call site's choice (§2) — an unattributable shape still refuses.
- **`sameFile`/inode is still never used** — the terrain survey confirms crisol has no FS-identity primitive and this RFC does not add one; identity stays textual (Non-goals).

## Alternatives considered

- **Sprinkle `toLowerAscii`/`normalizedPath` at the comparison sites.** Rejected: the terrain survey shows 15+ canonicalization spots already drift because there is no single seam; adding a fold at each membership/hash site multiplies the drift and leaves every *missed* site a silent Windows bug. A distinct type makes the omission a compile error.
- **Inode / `GetFileInformationByHandle` file-id as identity.** Rejected (Non-goals): volume-local, undefined for not-yet-existing diff targets, and un-portable into RFC-0005's attested cache wire — the very wire whose keys must stay stable.
- **Fold eagerly and store only the folded form.** Rejected: staleness re-opens the real file (`depgraph.isEntryStale`) and humans read logs — both need the real-case spelling. Hence the `rel`-only storage with `fold` as a policy field, folding only at compare time — never at key time (Fork C), never a second derived string persisted (§1).
- **A per-platform `#define` fold policy.** Rejected: case sensitivity is a volume property, not an OS property (case-sensitive Windows per-dir flag; case-sensitive APFS; case-insensitive Linux mounts) — and a project's own roots can straddle two volumes. The probe, per root (§3), is the RFC-0007 capability posture applied here.
- **On-disk-case normalization ("Option A") at classify time, and a deterministic canonical-representative merge ("Option B") — round-2/round-3 history, both superseded by `A0-spike`.** Round 2 considered two fixes to §4's determinism gap: (A) have `classify` query the real filesystem case for every EXISTING file (a componentwise directory-entry match on POSIX, `GetFinalPathNameByHandle` on Windows) and normalize `rel` to it, a not-yet-existing diff target passing through as-given since it only ever feeds folded membership, never a key; or (B) let a folded-equivalence class pick its representative deterministically — the lexicographically-minimum raw `rel` — via `canonicalMerge`/`CanonicalSet`, never by insertion order. Round 2/3 chose B over A: A reintroduces a filesystem case-QUERY into identity construction for every existing file — softening the **locked** "textual, not inode" non-goal this RFC otherwise holds exactly — for a benefit (a key spelling that additionally matches the true on-disk case) that B did not need in order to buy either soundness or fleet-portability, and B was cheaper: a string comparison on an actual fold-class collision, versus a directory-entry read or handle query per closure member, always. `A0-spike` then made the choice between them moot: Nim itself resolves every manifest-origin spelling to the on-disk real case before a manifest entry is ever emitted, so the fold-class collision both options were designed to resolve never arises via the manifest path at all (§4). Neither an FS case-query (A) nor a textual representative-selection merge (B) is needed; `canonicalMerge`/`CanonicalSet` are REMOVED.
- **Split the de-POSIX suite sweep into its own RFC-0010.** Considered; kept together (see §Stages) because full-suite Windows green is the *acceptance that proves the identity works* on a native case-insensitive volume — the abstraction and its liveness proof should not land in separate RFCs. Structured as a separate stage so it can proceed in parallel once the identity is stable.
- **depRoot identity as foreign-absolute-carried-forward.** Rejected in favor of root-tagging (Fork A). Keeping today's fallback — a depRoot member's identity is simply its absolute native path — is smaller and backward-compatible, but it enshrines the exact wart this RFC exists to close: a machine-local path baked into an attested key, and a type (`ProjectPath`) whose name lies about what it holds. Root-tagged `TrackedPath`/`TrackedRoots` is deeper: portable and attestable by construction, and it dissolves the multi-volume fold-policy risk for free (each root probes for itself, §3) instead of merely documenting it.
- **`Entrypoint.path` migration as surface-only (no additive ladder).** Rejected in favor of the full additive ladder (Fork B). Introducing `TrackedPath` only at the membership/key surfaces and leaving `path: string` in place permanently is a much smaller blast radius, but it forfeits the enforcement the RFC's motivation stakes its case on: `path: string` remains a live, un-canonicalized alternative that every future call site can reach for instead of `tp`, so "un-canonicalized comparison is a compile error" would be true only where someone remembered to use the new field. The ladder (additive `tp` alongside `path`, one surface migrated per slice, `path` removed via a compiler-enumerated sweep) pays a larger, bounded cost once for a permanent guarantee — the same trade RFC-0007's `A1` ladder made for `ProcessResult`.
- **Always fold, unconditionally.** Rejected: on a case-sensitive volume, folding aliases two genuinely distinct files (`Foo.nim`, `foo.nim`) into one identity — an unsound wrong-hit, not a conservative default. Probe-driven, per-root folding is the only policy that is sound on every volume it runs on.
- **Fold cache keys along with comparisons.** Rejected (Fork C, §4): keys derive from Nim's own on-disk-canonical spelling of each discovered dependency (§4, `A0-spike`) — a fact of the committed tree, never from the diff — so folding them buys no additional warm-hit coverage: the diff's case never reaches a key at all (it reaches only membership, which already folds), and the one recorded spelling a key ever sees is already the on-disk case, with no fold-class collision to resolve before a key is built. Folding keys ON TOP of that would cost real soundness on a case-sensitive volume (aliasing distinct files' keys) and introduce a cross-policy fleet-cache split that unfolded keys avoid entirely. Trading soundness for a hit rate that never materializes is the wrong call for a tool whose value is sound selection, not throughput (MEMORY → crisol-value-is-selection).

## Stages & slices

Dependency-correct order: **A0-spike (empirical gate) → A (identity) → B (suite de-POSIX + full green)**. Stage A produces and proves the load-bearing property's selection half on the real `crisol` binary via self-contained conformance tests (the D2a-6 pattern — no `std/posix` test helpers), so it is provable on the existing `windows-latest` and `macos-latest` legs **before** the Stage-B sweep widens the windows leg to the whole suite. `A0-spike` gates entry into Stage A itself (round-3, R3-1): it is a cheap, throwaway empirical check of an assumption Option B's whole determinism argument rests on (§4) — this RFC is not `/tdd`-ready until it runs, and its pre-committed decision tree (below) means the A/B choice is not re-litigated mid-build regardless of the answer. Every Stage-A slice from `A0` on keeps Linux byte-identical (`fpNone` on a single-root project ⇒ fold is identity, `keyBytes` never folds regardless of policy ⇒ existing keys/wire unchanged); that invariant is the regression safety net for the whole retrofit, and `A0`'s golden vectors — including a vendored, frozen reference implementation for the depRoot cases that cannot be literal-byte-pinned (below) — are what make it checkable rather than asserted.

**Blast-radius honesty:** the identity retrofit is whole-program (the terrain survey ranks 8 modules; feasibility later measured 20 `src/` modules reading `Entrypoint.path`, ~106 sites, plus 74 test files / 221 sites constructing `Entrypoint(...)`); no single agent holds it. ## Contract impacts

- **RFC-0005 wire:** unchanged on a single-root, case-sensitive project (`keyBytes == rel == today's bare string` regardless of fold policy, since `keyBytes` never folds — Fork C); every attested `StoredEntry`/ledger/soundness key stays bit-identical. A project using `depRoot`s gets a **new** key shape for those members — the root-tagged, portable `dep:<name>/rel` form replaces today's raw absolute native path (the tag is resolved to this shape via the root's configured NAME — §1/§4 — never a bare ordinal, so a later config reorder cannot silently point an old attested key at a different root) — but those keys were never fleet-portable before this RFC, so there is no prior fleet entry to invalidate. No `storageFormatVersion` bump required for the project-relative case; `A5` ships the golden-vector test pinning the Linux keys, and `A0`'s goldens include a depRoot member specifically to make the new key shape checkable.
- **Canonicalization-fork resolution, settled empirically (`A0-spike`, round 3).** §4's original premise — that closure/dep-graph membership derives from a deterministic on-disk walk — was FALSE (closure members are compiler-manifest/import-origin, not `walkDir`); round 2 replaced it with a deterministic canonical-representative merge rule ("Option B": lexicographically-minimum `rel` per fold-equivalence class, `canonicalMerge`/`CanonicalSet`) to keep identity purely textual, honoring the LOCKED "textual, not inode" non-goal, rather than an on-disk-case filesystem-query alternative ("Option A", Alternatives considered). `A0-spike` then tested the premise both options were built to address and disproved it: Nim itself resolves every manifest-origin spelling to the on-disk real case before a manifest entry is ever emitted, so no fold-class collision between manifest-origin spellings ever arises and no representative-selection rule is needed. `canonicalMerge`/`CanonicalSet` are REMOVED (§4); `keyBytes` is deterministic by construction on the empirical fact Nim's own resolution establishes. This is a design correction to how the property is achieved, not a key-shape change: single-root Linux keys are bit-identical either way.
- **`Entrypoint.path` type change:** additive first (`A3a-i` adds `tp: TrackedPath` beside `path: string`), then removed entirely at `A-final` via a compiler-enumerated sweep plus the sanctioned scripted test-construction migration through a pinned `tests/support/testEp` helper (Fork B). Ripples through `discover`/`narrow`/`depgraph`/`runner`/`planner`/`pipeline`/`workerplan` across the ladder; serialized as `rel` (via the `display()` accessor) throughout (unchanged JSON shape) — entrypoints are always `rootTag 0`, so no root-name qualification is ever needed for this particular surface.
- **`ClosureEntry.closure` / RFC-0008 boundary contract.** `ClosureEntry.closure` is documented as a public CLI wire contract (`crisol.nim:312`, "project-root-relative forward-slash") that was already false for a `depRoot` member (§Summary's `fnv.nim:68` finding). This RFC settles it: a `depRoot` member's wire spelling IS its `keyBytes` form (`dep:<name>/rel`), never a bare project-relative guess; the `jsonout` schema revision this lands under is bumped and named at `A2` (`RunSchemaRevision`, `jsonout.nim:263`, currently 24 → 25). For RFC-0008: a runtime-observed native path that classifies `pcOutside` (outside every tracked root — the common case for most observed inputs) can never feed a cache key (`NativeAbs` carries no root tag, §1); 0008's evidence for such an input must be content-hash-only and treated as uncacheable-by-identity, never coerced into a `TrackedPath` it does not have. This paragraph is the contract 0008 inherits.
- **New per-root probed capability** (`FoldPolicy`) joins RFC-0007's evidence posture — reported per tracked root, and never required. **Correction (round-1):** an earlier draft called `fpNone`-on-probe-failure "the safe default"; it is the *opposite* — on a case-insensitive volume, `fpNone` makes a case-variant diff spelling miss the closure and **under**-select (the exact unsound miss §Motivation exists to prevent), while `fpAsciiLower` on a truly case-sensitive volume can alias two distinct files' keys. The two consumers (selection membership vs. cache keys) have **opposite** safe directions, so no single silent default is safe for both — and, per Fork C, they no longer share a policy at all: membership folds, keys never do. Round-2 resolution (§3): the fold policy is obtained by an authoritative **OS query** per root (rarely fails, and on Linux never touches disk for a plain ext4 mount) — falling back to a read-only directory-entry probe before ever requiring write access; on genuine double probe failure the run **fails safe on both axes** — `--changed` degrades to a full run, cache store/read is skipped for that run, and comparisons made during it use `fpNone` while the resulting dep graph is never persisted (§3) — never by silently picking a fold pole and never by letting a later run trust an uncertain graph.
- **amoxtli (first consumer) lockstep migration (round-3, R3-9).** `amoxtli/src/testkit/tier_gate.nim:1001-1009`'s `normalizeClosureEntries` calls `normalizeAbs(p)` on each `crisol closure --json` member; once a depRoot member's wire spelling is its `keyBytes` form (`dep:<name>/rel`, above), `normalizeAbs` produces a nonexistent absolute path, the heavy-set intersection stops matching, and amoxtli's tier gate goes silently green on real violations — stale-green, the exact failure mode crisol exists to prevent, the moment any of amoxtli's three configured dep roots puts an out-of-tree member in a closure. `A3d-iv` bumps `ClosureV1Revision` 2→3 and updates `closureToJson`/`api.closureReport` to emit the new spelling; amoxtli's own migration (keyed on the rev-3 marker) is amoxtli's to make, but this RFC names the coordination so it is not discovered as a production incident.
- **RFC-0007 D2b** closes here (its acceptance = Stage `B4b`); RFC-0007 line 555 gets its `- [x]` tick.

## Risks accepted

- **ASCII-only fold (round 1).** `fpAsciiLower` folds `A–Z` only. A filename pair differing solely by the case of a **non-ASCII** letter would mis-split on a case-insensitive volume. Accepted because a portable full-Unicode fold cannot match the kernel's own (locale/version-dependent) table, and matching it wrong reintroduces the split; real Nim source filenames are ASCII. `FoldPolicy` is an enum so a future `fpUnicode` is additive.
- **8.3 short names / junctions.** Pure-textual identity does not unify `FOO~1.NIM` with `foolong.nim`, nor a junction with its target. Accepted: neither git-diff nor `walkDir` discovery emits short names, and closure is deliberately lexical (not realpath) for M10; a user hand-passing an 8.3 path is out of scope (Non-goals).
- **Degraded-mode cost.** When a root's OS-level case-sensitivity query and the read-only fallback (§3) both fail to answer — the root is genuinely empty and permissions block the query itself — and even the last-resort create-and-stat fails, the run fails safe on both axes: `--changed` becomes a full run and the cache is bypassed for that run. Comparisons made during such a run use `fpNone` (§3/§4) — never a silently chosen fold pole — and the resulting dep graph is not persisted, so a later, healthy run never inherits an uncertain policy. Correct, but slower; reported in evidence so it is never silent. The read-only fallback and the Linux OS query (§3, round 2) make the double-failure case materially rarer than round 1's create-and-stat-only path, in particular for a read-only dep root (a milpa CAS mount), which round 1 would have wrongly required write access to just to answer the question.
- **Mapped drives & UNC aliasing.** `Z:\proj` (a mapped network drive) and `\\server\share\proj` are one directory with two textual identities. Pure-textual identity does not unify them — same class as the 8.3/junction acceptance above. (A `\\?\`-prefixed spelling is NOT in this class: `nativeCanonicalize` strips it on ingest — §2 — so it unifies with the unprefixed form; this bullet is only the genuinely unfixable mapped-drive-vs-UNC-share case.)
- **NTFS trailing dot/space stripping.** `foo.nim ` ≡ `foo.nim` at the Win32 layer; textual identity treats them as distinct. Accepted (neither git nor `walkDir` emits such spellings).
- **Per-directory case-sensitivity.** A case-sensitive subtree (Windows per-dir flag / WSL) under a case-insensitive root is probed only at the root, so nested files may fold under the wrong policy. Accepted as rare; detectable later by probing per-directory if a consumer needs it.
- **`\\?\` long paths.** `nativeCanonicalize` strips a leading `\\?\`/`\\?\UNC\` prefix on ingest (§2) so root-matching is prefix-independent; `A1`'s conformance suite decides directly whether `toNative` must re-add it, rather than deferring: a deliberate >260-character path drives `toNative`'s round-trip in-slice, and the RED result determines whether Win32 calls need the prefix re-added on the way out. Because every native Win32 call site consumes `toNative`'s output through the one boundary, the decision made there propagates everywhere automatically. Residual risk is narrow: a Win32 API call that reaches a path without going through `toNative` at all would still need its own prefixing, out of this RFC's scope.
- **Slug-derived stateDir path length.** `planner.binPath`/`cachePath`, the cache sink, and per-entrypoint nimcache directories are built from `planner.slug` (§4/`A5b`), which is keyed off `keyBytes` but whose READABLE prefix still escapes/doubles every non-alphanumeric byte for legibility — on a deeply nested project this prefix, joined under a Windows `stateDir`, can be the longest path crisol itself creates, and none of it routes through `toNative`'s long-path handling (above) because it is never itself a tracked-file identity. Accepted with a bound: the slug's readable prefix is capped at a fixed length (the trailing hash16 is already sufficient for uniqueness on its own), so the joined path has a known worst case; if that bound is ever insufficient for a real project, the fix is a shorter cap or a `stateDir` closer to the root, not a change to identity.
- **NFC/NFD Unicode normalization.** A filename created under one Unicode normalization form and referenced in a diff under the other (a real APFS behavior — HFS+/APFS normalize on write) folds to two distinct `TrackedPath`s under this RFC's case-only fold policy — an under-selection of exactly the kind §Motivation exists to prevent. Accepted for round 1: crisol's own sources are ASCII, and a portable NFC/NFD-aware fold carries the same locale/version-table risk that kept `fpAsciiLower` ASCII-only (above). Cheap mitigation, not a full fix: a non-ASCII byte anywhere in a changed-set name, on a root where folding is active, triggers the same conservative lever already used for a genuinely degraded probe (§3) — fall back to a full `--changed` run rather than trust the fold for that name.

- **A logged spelling may differ in case from what the user typed (round-3 R3-22, revised post-A0-spike).** A manifest-origin `rel` is Nim's on-disk real case (§4, A0-spike), so logs and errors (`display(tp)`/`$tp`) show the file's true on-disk spelling — which, on a case-insensitive volume, may differ in case from a case-variant a user typed in a diff or on the CLI. Accepted: this is the *correct* case, not an arbitrary representative, and `toNative` correctness is unaffected (the folded identity opens the identical file regardless); a cosmetic log-fidelity note, not a soundness cost.
- **Windows reserved device names (round-3, R3-27).** `CON`, `NUL`, `AUX`, `COM1`…`COM9`, `LPT1`…`LPT9` are reserved at the Win32 layer; a committed file or diff-named path spelled `NUL.nim` (or a directory component `aux`) must classify without throwing — `classify`'s totality is pinned to cover these names explicitly (`A1` vector) rather than leaving them an unconsidered edge of the total function. None exist in-tree today (verified via `git ls-files`), but a `windows-latest` CHECKOUT of a future such name would fail before any test ran if classification silently assumed it could not occur. Accepted as a pinned-total, not a prevented, case: `classify` never refuses, it decides (textually, like any other name) which arm such a name lands in.

Two risks the previous draft carried — **multi-volume projects** (a depRoot on a different-sensitivity volume folding under the wrong policy) and **cross-policy fleet cache split** (a distributed cache shared by differently-folded hosts missing across the boundary) — are resolved by this round's design rather than accepted: each `NativeRoot` probes and carries its *own* `FoldPolicy` (§3, Fork A), so a dep root never inherits the project root's policy; and cache keys never fold at all (§4, Fork C), so two hosts with different case-sensitivity discover the same on-disk bytes and — because Nim itself resolves every manifest-origin spelling to the on-disk real case (§4, `A0-spike`) — produce the same `keyBytes` regardless. There is no folded key, and no non-deterministic representative, to split across a fleet.
