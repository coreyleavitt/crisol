# crisol

A host-side, out-of-process, assertion-agnostic Nim test runner and impact-analysis tool.

crisol discovers test entrypoints, compiles and runs them in parallel with per-entrypoint isolated nimcaches, aggregates results with continue-on-failure, and — given a git diff — runs only the tests a change actually affects.

## What crisol is not

- Not an assertion library — `std/unittest` is unchanged; crisol runs any test binary.
- Not a property-testing library — proptest is a consumer that runs as a test binary under crisol.
- Not compiled into production binaries — it is build-time tooling only.

## Status

v0.1.0 — implemented and usable. Reviewed under RFC-0001, RFC-0002, and RFC-0003. Pre-1.0: the public API and config format may change before a stable release.

## Install

crisol is distributed as a local-path dependency via [milpa](https://github.com/knurl/milpa), the project's own dep resolver. There is no public registry.

Add it to your project:

```
milpa add crisol path/to/crisol
```

Then in your `.nimble`:

```nim
requires "crisol"
```

## Quickstart

1. Run `crisol init` in your project root to write a starter `crisol.kdl`:

   ```
   crisol init
   ```

2. Edit `crisol.kdl` to match your layout if needed (the generated file targets the conventional `tests/unit/test_*.nim` layout out of the box).

3. Run your tests:

   ```
   crisol run
   ```

4. Inspect the plan before running:

   ```
   crisol list
   ```

The conventional layout — `tests/unit/test_*.nim` and `tests/integration/test_*.nim` — works with zero config (crisol falls back to built-in groups when no `crisol.kdl` is found).

## Environment variables

| Variable | Effect |
|---|---|
| `CRISOL_SINK` | Path to the structured-results sink file. Set automatically by the executor for each test binary; do not set this yourself. |
| `NO_COLOR` | When set (any value), suppresses ANSI colour in crisol's output. |
| `FORCE_COLOR` | When set, forces ANSI colour regardless of whether stdout is a TTY. |

## Example `crisol.kdl`

The canonical starter config is what `crisol init` writes. Run `crisol init` to get it; the content below is reproduced for reference.

```kdl
// crisol.kdl — canonical starter configuration
// Generated by `crisol init`.  Edit to suit your project.

// ---------------------------------------------------------------------------
// Global settings (all optional — defaults shown)
// ---------------------------------------------------------------------------

// jobs 0                    // 0 = auto (max(1, cpu_count - 2))
// timeout-secs 300          // per-entrypoint run timeout
// compile-timeout-secs 600  // per-entrypoint compile timeout
// max-output-bytes 10485760  // stdout+stderr cap per entrypoint (10 MiB)

// State directory (relative to this file).  Change only if .crisol/ conflicts.
// state-dir ".crisol"

// ---------------------------------------------------------------------------
// Groups — at least one required
// ---------------------------------------------------------------------------

group "unit" {
    // Globs are relative to the project root (the directory containing this file).
    globs "tests/unit/test_*.nim"
}

// Opt-in group example: only runs when --all-groups or --group integration is passed.
// Remove or uncomment and customise as needed.
//
// group "integration" {
//     globs "tests/integration/test_*.nim"
//     opt-in #true
// }

// Gate example: run this group only when CI=true is set in the environment.
// Gates are evaluated at runtime; a closed gate skips the group (not an error).
//
// group "slow" {
//     globs "tests/slow/test_*.nim"
//     opt-in #true
//     gate "CI"
// }
```

## CLI reference

```
crisol run  [<path>...] [--group <name>]... [--all-groups]
            [--jobs <N>] [--timeout <secs>] [--fail-fast]
            [--dry-run] [--json] [--force-compile]
            [--failed] [--changed [--base <ref>]]
            [--filter-tag <tag>]
crisol list [<path>...] [--group <name>]... [--all-groups] [--json]
crisol clean [--all] [--config <path>]
crisol init [<path>] [--force]

crisol --help | -h
crisol --version | -V | version
```

### Subcommands

**`run`** — Discover, compile, and run test entrypoints.

**`list`** — Show what would run (the plan) without compiling or running anything. Shares the same discovery and gate logic as `run`.

**`clean`** — Prune orphan nimcache and binary directories and stale depgraph entries. `--all` removes the entire `.crisol/` state directory. `--config` overrides the config file path.

**`init [<path>] [--force]`** — Write the canonical starter `crisol.kdl` (default: `./crisol.kdl`). Refuses to overwrite an existing file unless `--force` is given.

**`--version` / `-V` / `version`** — Print `crisol <version>` and exit.

### Flags for `run` and `list`

| Flag | Effect |
|---|---|
| `<path>...` | Restrict discovery to these paths or globs. Each path resolves to its owning group(s): a path matched by one group runs with that group's flags; a path matched by **several** groups runs once **per** group (one leg per flag-set — the matrix, not a collapse of it); a path matched by no group runs ad hoc with global flags plus a warning. |
| `--group <name>` | Run only the named group(s); repeatable. Mutually exclusive with `--all-groups`. Alongside `<path>...`, narrows the candidate owners for those paths (a multi-group path to one leg). |
| `--all-groups` | Include opt-in groups (gates still apply). Mutually exclusive with `--group`. |

### Additional flags for `run`

| Flag | Short | Effect |
|---|---|---|
| `--jobs <N>` | `-j` | Parallel job cap. Default: `max(1, cpu_count - 2)`. Must be >= 1. |
| `--timeout <secs>` | `-t` | Per-entrypoint run-timeout override in seconds. Default: 300. |
| `--fail-fast` | | Stop launching new entrypoints after the first failure. |
| `--dry-run` | | Compute and print the plan; compile and run nothing. |
| `--json` | | Emit machine-readable `crisol/run/v1` JSON to stdout. |
| `--force-compile` | | Force recompilation of all entrypoints even when the binary is fresh. |
| `--failed` | | Re-run only entrypoints that failed in the last run (reads `.crisol/lastrun.json`; exit 3 if absent). |
| `--changed` | | Impact selection: run only entrypoints whose dependency closure intersects the git diff. Requires a git work tree (exit 3 otherwise). |
| `--base <ref>` | | With `--changed`: diff against `<ref>` instead of HEAD. **Requires `--changed`; supplying `--base` without it is an error (exit 3).** |
| `--filter-tag <tag>` | | Reporting-level filter: show only test records tagged `<tag>`. Entrypoints still run in full; only the report is filtered. Emits a warning to stderr when no records match. Exit code is unchanged. |

### Additional flag for `list`

| Flag | Effect |
|---|---|
| `--json` | Emit machine-readable `crisol/plan/v1` JSON to stdout. |

Each plan row is one leg — `path  [group]  <effective flags>  decision` — and the JSON entrypoint carries `flags` (the effective global-then-group list, in compile order). The same path under two groups with different flags is two rows.

### Exit-code table

| Code | Meaning |
|---|---|
| `0` | All selected entrypoints passed (or a pure listing succeeded). |
| `1` | One or more entrypoints failed, compile-failed, timed out, or were signaled. |
| `2` | crisol internal error — should not occur in normal operation. |
| `3` | Environment or configuration error: bad args, no entrypoints found, `--failed` with no prior run, `--changed` outside a git repo, etc. |
| `128+n` | Run interrupted by signal `n` (SIGINT / SIGTERM). |

The data-vs-structural distinction: exit 1 is a *data* result (tests ran, some failed); exit 3 is a *structural* problem (crisol could not set up or interpret the run).

## Config reference

Config lives in `crisol.kdl`, found by walking up from the current directory. Override with `--config <path>`.

### Global keys

All global keys are optional.

| Key | Type | Default | Notes |
|---|---|---|---|
| `jobs` | int | auto | Parallel job cap. `0` = `max(1, cpu_count - 2)`. |
| `timeout-secs` | int | `300` | Per-entrypoint run timeout in seconds. `0` = inherit (use built-in default). |
| `compile-timeout-secs` | int | `600` | Per-entrypoint compile timeout in seconds. |
| `max-output-bytes` | int | `10485760` | stdout+stderr capture cap per entrypoint (10 MiB). |
| `state-dir` | string | `".crisol"` | State directory, relative to the project root (the directory containing `crisol.kdl`). |
| `flags` | strings | (none) | Extra Nim compile flags applied to every entrypoint. Repeatable (each `flags` node appends). |
| `dep-roots` | strings | (none) | Additional source roots tracked for impact analysis (`--changed`). Repeatable. |

#### Memory-aware scheduling keys (optional)

When `mem-aware #true` is set, crisol gates new slots on available system memory to avoid OOM during parallel compilation.

| Key | Type | Default | Notes |
|---|---|---|---|
| `mem-aware` | bool | `auto` | Enable memory-aware slot admission. When unset, crisol probes `/proc/meminfo` and gates on memory if available. |
| `mem-budget-mb` | int | system RAM | Total memory budget in MiB. `0` = built-in default (system RAM). |
| `mem-per-job-mb` | int | built-in | Estimated MiB consumed per parallel compile+run slot. Must be > 0. |
| `mem-per-run-mb` | int | built-in | Estimated MiB consumed during the run phase (after compile). Must be > 0. |

### Per-group keys

Groups are declared with `group "name" { ... }`. At least one group is required when a `crisol.kdl` is present.

| Key | Type | Default | Notes |
|---|---|---|---|
| `globs` | strings | (required) | Glob patterns for test entrypoints, relative to the project root. At least one required. Repeatable. |
| `opt-in` | bool | `#false` | When `#true`, the group is excluded from default runs; it only runs when `--all-groups` or `--group <name>` is passed. |
| `gate` | string | (none) | Environment variable name. If the variable is unset or empty at runtime, the group is skipped (not an error). |
| `timeout-secs` | int | global value | Per-entrypoint timeout override for this group. `0` = inherit global. |
| `max-jobs` | int | (none = uncapped) | Cap the number of parallel slots used by this group. Absent = uncapped; `1` = serial. `0` is a config error — use absence to express uncapped. |
| `flags` | strings | (none) | Extra Nim compile flags for this group (appended after global flags; repeatable, each node appends). |

A group denotes **globs × flags**: an entrypoint's identity is (path, effective flags), so the same files under two groups with different `flags` are two distinct entrypoints — separately compiled (own binary, own nimcache), separately cached, separately reported, and separately selected by `--changed` (each leg's import closure comes from its own compile, so a `when defined(foo)` import is in the `-d:foo` leg's closure only). This is how a config expresses a CI matrix:

```kdl
group "unit-refc" {
    globs "tests/unit/test_*.nim"
    flags "-d:debug" "--mm:refc"
}
group "unit-orc" {
    globs "tests/unit/test_*.nim"
    flags "-d:debug" "--mm:orc"
}
```

`crisol run` runs both legs; `crisol run --group unit-orc` runs one; `crisol run tests/unit/test_x.nim` runs that file under both (add `--group` to pick one). Per-group flags only append to the global set — a group that needs to escape a global flag argues for not making it global.

### Group-selection model

Three mechanisms select which groups run:

- **Default (no flags):** runs all groups where `opt-in` is `#false` and all gates pass.
- **`--all-groups`:** runs all groups including opt-in ones; gates still apply (a closed gate skips the group regardless).
- **`--group <name>`:** runs exactly the named group(s); opt-in is bypassed; gates still apply.

`--group` and `--all-groups` are mutually exclusive; specifying both is a usage error (exit 3).

## Library embedding

To use crisol as a library from Nim code, import only `crisol/api` — that is the contracted public surface.

```nim
import crisol/api

# Run all default groups (no-config walk-up from cwd):
let report = runTests()
echo "exit code: ", report.exitCode
echo "passed: ", report.summary.passed, " / ", report.summary.total

# Run only the unit group with parallel jobs capped at 4:
let r2 = runTests(RunOptions(
  selection: namedGroups("unit"),
  jobs:      4,
))

# Inspect the plan without running:
let plan = planTests(RunOptions(
  selection: defaultGroups(),
))
for ep in plan.entrypoints:
  echo ep.ep.path, "  [", ep.ep.group, "]"
```

Key types in `crisol/api`:

- `RunOptions` — all inputs to `planTests`/`runTests` (config path, group selection, narrowing, jobs, timeout, callbacks, etc.).
- `RunReport` — output of `runTests`: `.status` (`rsOk`/`rsStructural`/`rsInterrupted`), `.exitCode`, `.summary`, `.results`, `.error`.
- `PlanReport` — output of `planTests`: `.entrypoints`, `.jobs`, `.gatedOut`, `.warnings`, `.settings`.
- `defaultGroups()`, `namedGroups(...)`, `allGroups()`, `filesSelection(...)` — group-selection constructors.
- `noNarrowing()`, `failedOnly()`, `changedOnly(baseRef="")`, `failedOrChanged(baseRef="")` — narrowing constructors.

`runTests` never raises for expected conditions (structural problems are encoded in `RunReport.status`/`.error`/`.exitCode`). `planTests` raises `CrisolError` on structural problems.

The schema-version constants for the JSON documents are exported from `crisol/api`:

- `RunV1Schema = "crisol/run/v1"` (from `crisol/jsonout`)
- `PlanV1Schema = "crisol/plan/v1"` (from `crisol/planview`)

## Structured results — concrete recipe

Test binaries can emit per-test records so crisol aggregates pass/fail/skip counts and supports `--filter-tag`. Two paths:

### Path A: drop-in shim

Replace `import std/unittest` with `import crisol/unittest_shim`:

```nim
import crisol/unittest_shim  # re-exports all of std/unittest

suite "my tests":
  test "example":
    check 1 + 1 == 2
```

No other changes needed. The shim registers a `CrisolFormatter` that emits structured `TestRecord`s to `CRISOL_SINK` (set automatically by the executor). When `CRISOL_SINK` is unset, every emit call is a no-op — the binary works standalone.

**Limitation:** the shim hardwires empty tags (`@[]`) for every record. `--filter-tag` is therefore NOT reachable via the shim. Tag support in `unittest_shim` is a planned future enhancement.

### Path B: raw emitter (supports tags)

Use `crisol/report` directly for full control, including per-test tags:

```nim
import crisol/report
import crisol/types

initReport("tests/unit/test_mymodule.nim")

# ... run a test ...
emit(TestRecord(
  name:       "addition works",
  status:     rsPass,
  durationUs: 42,
  msg:        none(string),
  tags:       @["fast", "arithmetic"],
))
```

`initReport` reads `CRISOL_SINK` from the environment (set by the executor). When the variable is absent, every `emit` call is a no-op. Call `initReport` once before any `emit` calls.

## Design

See [`docs/rfc/`](docs/rfc/) for the full design, architecture, and decision records.

### What a closure tracks

`--changed` selection and compile avoidance both work from each entrypoint's
**source closure**, derived from the Nim compiler's own build manifest (never
from a hand-rolled import parser) and filtered to files under the project
root or a configured `dep-roots` entry. Per (path, effective flags) leg, the
closure contains:

- every Nim module the compile reached (imports, including `when defined(...)`-gated ones, resolved through any `--path`);
- every `include`d file, every `staticRead`/`slurp` target, and the
  `nim.cfg`/`config.nims` files the compiler read (crisol compiles with
  `-d:nimBetterRun` so Nim records them; the define is not part of the
  entrypoint's flags or identity);
- every `{.compile: "file.c".}` C/C++/ObjC source and every `{.link: "file.o".}` prebuilt object.

Editing any tracked file recompiles the entrypoint on the next run and
selects it under `--changed`. Two shapes cannot be tracked and are handled
**fail-closed** — crisol warns on stderr and recompiles + force-selects the
entrypoint on every run until fixed: the tuple form
`{.compile: ("pattern*.c", "$1.o").}` (Nim erases the source path from the
object name; use the single-path form), and object paths that are not
absolute (`--noAbsolutePaths`). Not tracked by design: `gorge` (a shell
command, not a file) and the C headers a `{.compile.}`d source `#include`s
(Nim's own external-object cache ignores headers as well).

## Development

crisol dogfoods itself via a `nimble test` task (self-discovering
`tests/unit/test_*.nim` + `tests/integration/test_*.nim`, run serially).
All toolchain commands run in a containerized dev image (see `./dev help`):

- `./dev test` — the main suite (unit + integration).
- `./dev timing` — the serial, deadline-sensitive `tests/timing/` leg
  (excluded from `./dev test`; flakes under concurrent host load).
- `./dev check` / `./dev build` — type-check / compile the package.

CI (`.github/workflows/ci.yml`) runs both legs on every push to `main` and
every pull request.
